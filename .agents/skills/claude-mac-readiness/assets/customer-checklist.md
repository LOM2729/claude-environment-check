| 项目 | 在哪里、怎么处理 | 完成标志 |
| --- | --- | --- |
| □ 01 目标与恢复 | 确认操作的是客户 Mac、实际用户和所需客户端；远控时准备客户本机可执行的恢复步骤 | 目标明确，配置中断后有恢复办法 |
| □ 02 时间与时区 | 系统设置 → 通用 → 日期与时间；分开记录自动校时、自动时区和城市。需要手选时区才关闭自动时区，通常保留自动校时 | 时间准确，时区标识和自动选项符合客户目标 |
| □ 03 系统语言／地区 | 通用 → 语言与地区；按需设置界面、地区格式，保留原语言与输入法 | 日期、数字格式及常用软件正常 |
| □ 04 浏览器语言 | Chrome／Edge 设置 → 语言：检查网页首选语言排序；菜单语言另核对。Mac 可查看“语言与地区 → 应用程序”的单应用语言支持 | 完全重开后菜单与网页语言分别符合目标；不默认删中文 |
| □ 05 浏览器档案 | 确认客户实际 Profile、已有代理扩展及组织管理策略；需隔离工作场景才新建档案，保留原档案 | 检查发生在实际使用档案，不以临时档案代测 |
| □ 06 文件与备份 | 识别完整 YAML、规则片段、节点订阅或小火箭 conf；保留原件，备份当前选中配置和必要应用开关 | 备份读回可用、候选差异清楚，不含无关重写／脚本改动 |
| □ 07 导入配置 | Clash Verge：订阅／配置 → 新建本地或支持的拖拽；小火箭：配置 → 导入／文件分享，再选中。规则片段走扩展入口 | 新配置存在且被选中、核心无加载错误；原配置仍可恢复 |
| □ 08 节点与接管 | 在代理客户端核对所选组、节点、Rule／Global／Direct 与系统代理／TUN；不要照抄端口 | 实际本地入口、接管范围和出站选择与方案一致 |
| □ 09 分流 | 检查 Claude 域名／功能、组引用、规则优先级、兜底和 DIRECT／fallback；保留 LAN／企业 VPN／远控例外 | 真实请求命中正确规则／出站，必要本地业务可用 |
| □ 10 DNS 与 DoH | 网络 → 当前服务 → 详细信息 → DNS；结合 `scutil --dns`、代理 DNS、生效配置、浏览器安全 DNS | 系统／代理／浏览器各层责任明确，节点 bootstrap 不循环 |
| □ 11 TYPE64／65 | 检查 SVCB／HTTPS 查询的支持、过滤和上游；与 A／AAAA 分别核对；DNS64 另列 | 记录响应／超时和功能表现；不把无答案当作过滤已生效 |
| □ 12 IPv4／IPv6 | 分别核对接口、本机到节点、节点到目标；检查当前代理的 IPv6 和 DNS AAAA 设置 | 已测范围明确；不把单次 IPv6 失败记成已关闭／无旁路 |
| □ 13 WebRTC／UDP | 实际浏览器 Profile 中，用已批准检测检查候选与同地址族出口；核对 STUN、QUIC、UDP 不支持时回退 | 有效样本／检测受限分开；调整后所需通话／共享可用 |
| □ 14 网页／Desktop | 各自验证打开、登录和客户已有会话中的最小功能；按用途检查附件、Artifacts／组件 | 页面加载和实际任务成功；无凭据 HTTP 探测不算账号通过 |
| □ 15 Claude Code | 在实际启动终端核对命令、版本、认证来源、代理覆盖；GUI、IDE、后台、SSH 路径分别看 | CLI 真实请求可用，订阅／API／网关来源符合预期 |
| □ 16 持久化 | 核对代理自启、通用 → 登录项与扩展、订阅更新及覆写顺序；区分 GUI 与核心进程 | 记录已实测的重载／更新结果，未重启则明确未测 |
| □ 17 故障演练 | 仅在批准且有独立恢复时测试节点坏、核心停、隧道消失、睡眠／换网；用新连接观察 | 明确阻断／回退／未知，恢复后重新验证网络和远控 |
| □ 18 交接 | 提供已改项、有效配置标识、实际测试范围、未测项、恢复方式及复验触发条件 | 客户知道怎么用、怎么恢复、哪些结论尚未成立 |

**每次改动记录：** 项目___　原值___ → 新值___　批准范围___　备份／回退___　读回___　功能复测___。

**每项结果：** □ 已完成　□ 未完成。未完成原因：___；下一步：___。修改前按所选模式取得具体批准；客户暂不修复仍存在的问题保持未完成。客户确认无关的项目不计入总数并记录范围原因。

**证据标签：** 官方／标准、第三方源码、个人经验／社区资料、用户提供、静态配置、模拟测试、目标机实测。配置声明、应用载入、进程采用和端到端观察分别记录；检测分数不等于账号安全结论。
