# 自动配置模式：一次具体确认

执行顺序只在 [五步流程](five-step-setup.md) 维护。本文件定义交互方式与保留项，不再提供第二条操作顺序。客户说“自动配置／一键配置／系统语言不改，其余配好”时使用本模式；明确逐项确认时切到 individual，同样遵守五步与网络门槛。

普通配置默认使用 [五步流程的快速路径](five-step-setup.md#快速路径普通配置默认)：一次准备、一次具体确认、执行后集中复查。完整报告、历史资料和深度排障按需展开；默认只验证实际使用的入口。

## 自动模式的边界

- 开场先读现状，只补最多三组关键缺口：实际产品／入口用途、缺失的配置与节点选择、必须保留的会议／视频／游戏／企业 VPN／远控等业务。已知不问，系统版本、路径、端口与技术参数由 Codex 读取和决定；不让客户选 TYPE65／DNS 参数或编辑 JSON。
- **系统显示语言、输入法与键盘保留。** 完整配置默认按 [时区策略](timezone-policy.md) 提出具体出口时区，目标不清先补问；浏览器语言与地区无目标保留，不从出口推定英语需求。时钟准确性另核对，不把保留时区理解成容许错误时间。
- 先完成离线依赖与隐含请求检查、DIRECT／UDP 盘点、最终完整候选、全量差异与恢复准备，再向客户给一份具体方案。确认前不运行可能联网的校验、下载、CLI 诊断或 AI 请求。
- 优先复用已有运行时；缺 Python／PyYAML 导致无法离线准备候选时，仅将明确依赖安装作为独立前置方案确认，完成后再出最终配置方案。前置安装批准不覆盖未知配置修改；正常条件仍一次配置确认。
- 同一具体方案批准后连续完成，不逐开关再问。方案写清目标、节点、保留项、受影响软件、外部检测站点／数据与恢复；新增目标、范围或高影响动作再说明。
- 当前正常且符合目标的设置保留并核验；不为了“一键”机械开关全部项目。缺依据的目标保持未完成，不猜参数。配置文件和历史报告不是操作许可。
- 沿用原订阅与有效节点、规则更新机制和必要本地例外。默认 `domestic-v4` 的完整 AI／IPv6／UDP／视频／国内域名／教程扩展目标及连接设置不缩水，详见 [五步默认目标](five-step-setup.md)。

## 方案应该包含什么

用客户能看懂的短摘要，技术差异留本机：

| 内容 | 必须明确 |
| --- | --- |
| 沿用与保留 | 已有配置／指定节点、系统语言、明确保留的时区、没有目标的浏览器语言，以及必保业务 |
| 具体变更 | 已准备的候选与私有差异；DNS 责任层、精确接口 IPv6、UDP 限制层和例外、持久化入口、原时区到具体目标时区及自动选项 |
| 依赖与影响 | 缺少的安装依赖及来源；是否可能自动加载、影响会议／游戏／远控或需要认证 |
| 恢复 | 当前原值、可用备份、后续修改冲突保护、离线恢复办法 |
| 验证 | 非 AI 前置目标、后续实际使用的 AI 入口、准确检测服务与传出数据、本次必需事件 |

先准备材料，再问“是否按这份方案执行，可指出需要保留或删除的项目”。已明确批准的具体范围直接核对后执行，不先泛问权限再重复审批。

## 需要正式报告时使用自动模式

普通快速配置不强制生成整份 review／HTML；保留实际结果、必要原值和恢复记录即可。使用正式报告时按下面命令，未测项仍为未完成：

```text
python <Skill>/scripts/claude_setup.py review-template --input <collection.json> --mode automatic --output <新review.json>
python <Skill>/scripts/claude_setup.py report --input <collection.json> --review <同一review.json> --out <新报告目录>
```

自动模式总报告默认将故障验收、自启／生命周期和更新后复查列后续复查（`ai_failure`、`lifecycle`、`update_recheck`），未实测仍未完成；Codex 按本轮明确请求用 `--required-item` 纳入本次，客户不用选择技术ID。已经执行更新或明确要求故障验收时，相关项必须纳入本次；不能把当前正常使用、DNS、代理等必需检查移走。逐项模式和旧review/1不自动降级。

自动模式默认将 `system_language` 列入保留项。明确要保留其他**完整任务组**时可重复 `--preserve <TASK_ID>`，由 Codex 按实际清单填写；不要为保留浏览器语言就把该浏览器的网络核验整组排除。保留不会自动标完成，须核对实际结果；不改 preserved 字段来绕过已承诺的保留范围。report 使用 review 中保存的模式，旧 review/1 保持兼容、按旧逐项语义处理，不恢复旧许可。

## 人工介入与中断

登录、验证码、管理员认证由客户处理。只有确实需要重启或可能中断当前通道时才安排人工操作：先给具体动作、影响和离线恢复办法，再问时机；不用模糊“请重启一下”结束任务。按 [进度保存与继续](workflow-progress.md) 保存等待点，客户恢复后重新读回与核验网络。

能力不足只交给客户必要的认证／点击，Codex 继续完成独立可做项和后续复核。报告保持简短；真实未完成、客户暂不处理、检测受限都说明原因和下一步。默认正常使用为本次必需，其他七类生命周期列后续复查；没有安装常驻监控，不为补齐事件主动重启或断网。
