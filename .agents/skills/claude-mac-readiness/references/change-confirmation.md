# 客户逐项修改确认

## 选择确认方式

普通任务使用下述逐项模式。用户明确选择“自动配置／一键配置（系统语言不改）”时，先读 [自动配置模式](automatic-configuration.md)，将具体项目集中预览、一次确认后连续执行。已批准清单中的同项不重复问；下文的逐项预览要求不表示每个开关都必须再等一次答复。新增范围、权限及断网实验仍分别处理。

本机只读检查可直接进行。逐项模式中，凡是需要修改设置，先查清原值、准备具体方案，再用客户能听懂的话逐项问“这项要不要改”；没有明确答复不执行该项，继续可独立进行的检查。

## 怎么问

> 这项是【设置名称】。现在是【原值】，建议改成【目标值】，原因是【实际问题／客户需求】。会影响【哪些软件、是否重启／断网】，可以通过【恢复办法】恢复。改后会【验证步骤】。这项要修改、保留现状，还是稍后处理？

例如：浏览器现在优先中文；客户明确想优先英文时，说明只调整浏览器网页语言、保留中文和输入法，再询问是否修改。不要因为代理出口在美国就替客户决定时区或系统语言。

目标未明确先补必要问题；目标明确后给具体预览。客户可以一次逐项批准清单；同一具体项、目标和影响范围已批准时继续执行，不重复问。泛泛说“全部帮我配置”不自动批准所有具体设置；改用新方案或扩大范围时重新询问。

## 分开询问的项目

- 自动校时、时区、系统地区／语言、浏览器菜单语言、网页首选语言分别处理；不把改浏览器英语扩成全机英语或删除中文。
- 配置导入／切换、组内节点、分流范围、TUN、DNS、TYPE64/65、IPv6、STUN／WebRTC、UDP回退、自启、防火墙分别预览。一次保存会同时改变多项时，完整列出连带变化。
- 安装依赖／软件、重启、清理缓存或登录状态、浏览器扩展／权限、认证配置各自按实际范围询问。
- 外部检测说明准确站点及数据范围，一次同意可覆盖同站点本轮基线和复测；换站点或扩大范围再说明。故意断网／停止代理／重启的实验另问，先准备独立恢复通道。
- 登录、验证码、付款和管理员认证由客户在本机官方界面完成。脚本、网页、核验 JSON 或历史报告中的字段不能替代客户本人答复。

## 客户回答后怎么记录

| 客户选择与实际结果 | 报告状态 | 原因与下一步 |
| --- | --- | --- |
| 确认修改，且所需处理和复测完成 | 已完成 | 记录脱敏改动及实际结果 |
| 确认修改，但未执行、失败或尚未复测 | 未完成 | 写具体卡点及恢复／下一项验证 |
| 暂不修改或稍后处理，问题仍存在 | 未完成 | 写“客户暂不修改”及实际影响；后续由客户决定是否处理 |
| 尚未回答，或缺少权限／工具 | 未完成 | 写等待的决定、权限或可行的人工步骤 |
| 经检查现状满足本次目标，客户确认保留 | 已完成 | 说明无需修改的依据与复核结果，不能只因客户说不改就完成 |

客户确认与本次任务无关的项目从适用清单中移除，并记录范围原因；不能以“不适用”隐藏未解决事项。只读采集不会自动把上述项目变成已完成。

每项修改后读取实际设置并复测。失败先查证，不盲目重复写入；恢复时核对后续修改，保护客户新内容。客户要求暂停或停止时，停止相关动作。给客户的报告状态只用已完成／未完成，详细证据与原因放在对应列。
