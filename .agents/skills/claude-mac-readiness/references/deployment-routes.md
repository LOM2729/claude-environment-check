# Claude 运行路线、出口来源与部署规划

只在用户比较路线、选择出口或明确需要 VM／VPS 部署时读取。已有设备和任务明确时沿用当前路线，不为普通修复重走问卷。比较方案先交付比较；实际安装、服务器访问和网络变更沿用本轮授权范围及恢复要求。

## 运行位置和出口位置分开选择

| 路线 | 适用目标 | 需核对的代价与边界 |
| --- | --- | --- |
| 本机 | 继续使用现有浏览器、Desktop、CLI 和项目 | 成本与维护较低；按实际程序核对代理采用及本地业务例外 |
| VM | 用户确实需要独立工作环境、快照或环境隔离 | 核对宿主资源、CPU 架构、客机支持、镜像与许可；客机与宿主分别取证，独立局域网地址不自动产生独立公网出口 |
| VPS 开发机 | 程序需要在远端持续运行，或需要远程开发环境 | 核对算力、存储、备份、可达性、流量费用和救援入口；远端程序、浏览器及本机显示端的路径分别记录 |

VPS 只作为代理服务器时，运行路线仍是本机或 VM。将远程桌面入口转发到另一台机器，也不会自动改变远程浏览器的出站代理。相关执行边界复用 [执行位置与进程路径](execution-paths.md)。

规划时给出一条首选及其理由，并说明什么条件下另一条更合适；不把三条路线当升级顺序，不从套餐 Pro／Max 推导必须买哪种网络资源。

## 固定出口的候选比较

| 来源 | 比较重点 |
| --- | --- |
| 托管代理／订阅 | 共享程度、是否真的固定出口、节点变更通知、实际稳定性、支持与取消条件 |
| 自建 VPS 代理 | 服务器和密钥控制权、维护成本、协议兼容性、带宽／流量计费、恢复与补丁责任 |
| 家宽／ISP 出口 | 实际共享方式、地址是否可能变化、服务商控制权、故障支持和目标时段表现 |

“家宽”“机房”“独享”“原生”等标签不能替代实际能力与信誉证据；不同数据库分类不一致时保留来源、日期和定义。先沿用已满足需求的出口，不因单次参考分数自动换节点。节点备注、入口 IP、代理链最终出口分别核对；日志中只保留必要脱敏摘要。

自建时先按用户实际使用的桌面、iOS、Android、CLI 列出协议／传输／TLS／UDP 支持矩阵，再决定服务端选项。逐客户端连接、出口和功能分别验收；桌面成功不代替手机成功。节点故障时按已约定的拒绝／回退行为处理，不静默切换出口。

## VM：先定义隔离和管理方式

1. 核对虚拟化平台、宿主架构、客机镜像、所需资源和真实应用兼容性；Omarchy、macOS 客机是上游选项，不是固定默认。
2. 在 NAT、桥接、host-only 等平台实际支持的模式中按目标选择。桥接增加局域网可见性，NAT 与宿主网络有关；两者都要在客机实际验证。已有 VM 先记录原网卡模式与快照，保留磁盘。
3. 先建立可恢复的管理入口和所需代理连接，再规划防火墙。共享目录、剪贴板和密钥只给必要范围；不复制带账号会话的镜像作为新环境。
4. 故障保护需检查真实核心、TUN、管理通道、已有连接和 IPv4／IPv6。重启、挂起／恢复、宿主换网按实际发生的场景复查。
5. 上游 Linux nftables 脚本不是 macOS／Windows 执行器。本轮源码审阅发现其回滚和持久化等缺口，见 [Guardian 能力边界](guardian-integration.md)；实际部署先按目标环境另出可验证方案。

## VPS：开发环境与网络服务分别规划

1. 从只读资源盘点开始：当前 OS／架构、内存可用量与 OOM、磁盘空间、现有服务和云控制台救援。按工作负载决定系统、swap、并发和桌面资源，不硬编码一个发行版或内存阈值。
2. 只有用户需要图形界面时才准备 Xvfb／noVNC；桌面服务采用受限监听和已批准的加密管理通道，检查监听地址、认证和防火墙。原始 VNC／WebSocket 端口不能因照抄示例而公开。
3. Remote-SSH、tmux 和保活各自验收：SSH 可重连、任务仍存在、正确会话可恢复。它们不自动恢复主机重启、进程崩溃或 OOM。
4. 区分入站访问控制与出站防直连。只有 INPUT 链的防火墙不能证明出口固定；默认出站拒绝也需检查既有 Allow、管理例外、进程、地址族和当前连接。
5. 对拟使用的脚本先核对版本、依赖、提权、下载、服务持久化、实际回滚和参数范围。上游链接供阅读，不作为直接执行授权，不运行未经审阅的管道下载脚本。
6. 完成后核对服务实际运行、有限监听、目标客户端、出口和恢复步骤；需要中断通道的动作继续由用户按已约定方式手动完成。

## 线路慢与断流

先比较同一客户端、目标、时段和数据量的基线，区分本地→中转、两服务器之间、出口→目标和应用负载。记录失败／重试、连接时间、TLS／HTTP 状态和实际业务表现；Ping 不能替代业务吞吐。吞吐测试的流量与费用先包含在检测范围里。

一次改变一个因素，再用同一方法复测。先查饱和带宽、CPU、内存、重传和方向差异，再考虑更合适的路由、中转、画面质量或 TCP 参数。BBR 是拥塞控制选项，不替换运营商路由；改 DNS 也不是线路升级。透明端口中转不自动加密，SSH 动态转发也不自动覆盖所有应用 DNS／UDP。

原值、前后结果和恢复动作进入本轮记录。内核、SSH、防火墙和持久服务变更需要可用救援；后台回滚任务存在不等于恢复已验证。
