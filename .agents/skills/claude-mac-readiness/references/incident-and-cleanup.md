# 故障分流、凭据事件与清理规划

用户报告现有问题时先解决当前阻碍，不重走完整环境问卷。一次收集必要事实：产品／提供方、客户端与执行位置、发生时间和时区、执行动作、脱敏错误、最近变更、已知工单或订单状态。复用已知信息，保留原始证据在用户本机。

## 按响应来源分流

先判断响应来自客户端、代理／网关、认证服务还是目标提供方。下面的 API 说明仅适用于对应官方 API，网页挑战页和第三方网关要按其实际响应解释。

| 现象 | 下一项检查 |
| --- | --- |
| DNS、连接或 TLS 错误 | 核对路径、解析责任、系统时钟、证书和代理；按 [分层排障](guardian-integration.md) 处理 |
| 401 | 核对认证类别、作用域、有效状态与启动入口；不轮试或输出秘密 |
| 403 | 官方 API 可能是资源权限；网页也可能是挑战或访问限制。查具体错误正文和来源，不能单凭状态码判封禁 |
| 429 | 区分速率、额度、月度／工作区消费上限等实际原因；有等待提示则遵守，消费上限不能靠持续重试解决 |
| 529／其他 5xx | 核对官方状态与实际错误类型；适用时有界退避，不先清账号或换出口 |
| 付款／权益冲突 | 转 [账单检查](billing-checks.md)，先查原渠道是否已扣款，避免重复购买 |
| 身份核验／明确停用 | 用户按官方流程核对要求与限制对象；记录事实并准备支持材料，不以换邮箱循环注册作为修复 |
| 原因不明 | 保留未完成，按最近变更和最小对照排查，不从风险分或封禁时间段编造唯一原因 |

[Claude 官方 API 错误文档](https://platform.claude.com/docs/en/api/errors)于 2026-10-31 核对：403 为权限错误，429 可涉及速率或消费上限，部分上限响应没有 Retry-After，529 为临时过载；执行时复核当前版本。SDK 可能已自动重试，增加外层重试前核对次数、总时限与副作用。流式请求即使先返回 HTTP 200 仍可能随后报错。

## 凭据疑似暴露

停止助手尚未发送的新增请求，记录暴露的类别、时间和影响范围；不把秘密复制到报告。说明官方撤销／轮换入口及依赖中断，由用户处理敏感认证动作。撤销不是可逆配置修改，不能把旧密钥当回滚方案。已在运行的用户任务按实际授权处理，不随意杀掉全部进程。

支持或申诉材料只写实际通知、时间线、影响、已执行步骤和待确认问题，附必要脱敏 request ID／订单状态。正文可先准备，发送给第三方是独立动作，沿用用户实际授权；不保证回复天数或退款结果。

## 只有用户需要时才规划清理

清理目标可能是损坏缓存、迁移、隐私整理、退出登录或卸载；先区分目的和精确对象。网络异常、KYC 或历史停用不自动触发删除日志、对话、密钥或设备标识。

- 先盘点实际平台、安装方式、配置根、当前写入者和所有权。保护项目、未提交代码、CLI 设置、Skills／插件、历史及当前控制通道；不能按名称关键词全盘删除。
- 预览精确路径与保留范围、原内容核验、备份／隔离和恢复步骤。可恢复隔离不自动等同独立备份；跨多个目录也不是原子事务。
- 只在授权范围内处理；写前和写后核对对象与内容。失败可能发生在写入之后，先对账实际状态再决定恢复，不能盲目重试或覆盖后续编辑。
- 审查 MCP／插件／hooks／网关时看具体来源、配置用途、数据范围和支持政策。自定义 BASE_URL 或关键词命中不足以判定“非法”；检查输出须在采集端过滤 URL 参数、命令参数和 hooks 中的秘密，不能只遮掩 env 键。
- 不以“删除查 IP 的记录会降低封号风险”为理由清理，也不将设备 ID／UUID 轮换纳入环境准备。
- 上游清理库有 POSIX 范围及 Mac 宿主限制；本次审阅未验证其在用户设备上的执行。精确事务方法可参考，现有执行脚本不直接移植为通用清理器。
