# 浏览器体检、参考分与泄露检测

只有用户要求或同意外部检测时才打开。优先使用其实际访问 Claude 的浏览器；另一个浏览器的结果不可代替。访问检测站会向该站披露当前出口 IP 及浏览器特征，先说明准确域名、目的与数据并取得该站点的确认。一次确认可以明确覆盖“同一站点的基线与本轮修改后复测”；换站点、换浏览器或扩大发送数据范围时重新说明并确认。不在客户未同意时批量打开多个检测站。

多来源工具还会联系页面之外的服务，首次说明应覆盖实际启用的来源与后台查询；同一已批准清单内的采样和本轮复测不逐个重复询问。仅打开本地页面不等于已同意其外部探测。桌面工具只读本机与联网检测分开核对；不展示或评分 App 自身的语言、时区来代替用户电脑及所选浏览器。

## 可选站点与记录

- Clearpath：复用已有桌面工具或网页版，在同页查看具体读数、来源、参考扣分及检查/调整入口。网页入口为 [Clearpath](https://rumoapi.com/check/)；使用前核实页面版本和实际可用模块，不能由本地源码版本推定已上线。桌面基础体检、浏览器助手和网页版的范围及评分模型分别记录，不能互相代测。
- [IPPure Claude 检测](https://ippure.com/claude)：记录页面当时显示的总分、满分/方向、连通性、出口、WebRTC、DNS、语言、Intl 时区、字体/Emoji 等实际出现的提示。
- [Net.Coffee Claude 检测](https://ip.net.coffee/claude/)：可作为另一个独立检测；其 Trust Score 与 IPPure 的分数定义不同，不合并、平均或直接比较。

每次记录目标设备、站点/工具版本、检测时间、浏览器及配置、是否启用 VPN/TUN、总分方向/模型与各项标签的简短转述；一并记录有效采样数、失败来源和未确认项，取得结果不等于通过。只在报告中保留国家/地区、ASN、是否观察到经基线核实的公网地址暴露等必要摘要；不保存完整公网 IP、原始 WebRTC candidate/SDP、浏览器指纹载荷或站点生成的私人链接。若页面没给分数，写“未显示”，不能补造。

## Clearpath 多来源结果

以下能力以本地网页 0.7.1 为参照，实际执行以目标页面为准。完整 API 联调用项目 README 的构建加 `start` 流程；助手本机的 `127.0.0.1` 页面不能作为远端客户设备的证据。只部署静态页面时，请求摘要/IP 归属接口可能缺失，应记为“接口未部署”，不能判用户网络异常，也不自动升级或发布工具。

联网前说明本轮准确目的域名及数据流：网页 0.7.1 包含 Cloudflare HTTP、BrowserLeaks/Surfshark/Fastly 随机 DNS 子域、Cloudflare/Google/Twilio STUN、ipify IPv4/IPv6 端点和 IPv6 备用 icanhazip/MyExternalIP、Claude/Anthropic 请求。后台接收本轮浏览器出口 IP，查本地类型库并向 RIPE NCC 发送该完整 IP 查归属；各服务会收到连接或查询所需信息。以当前页面与 README 的准确域名清单披露，不只说“访问 Clearpath”。不携带账号凭据、不调用模型；本机报告脱敏不能消除第三方或网关可能保留的日志。

每条网络卡片不一定对应独立实验；STUN 失败会使依赖它的路径对照缺数据，不能重复算作独立故障。WebRTC/IPv6/IP 类型的未知按“受限、数据缺失、未确认”解释，不归因于某个开关，除非已有目标机证据。

网页参考分为 100 减已确认扣分，越高只表示参考扣分越少。未知计分项不算零扣分，未齐时记录范围/待计分；网络项不参与这套分数，因此即使参考分已完整也可能有网络未知。桌面版权重可能不同，不能套用或合并分数。

可移植包说明：以上 Clearpath 版本细节来自历史实现研究，相关私有源码与历史报告未随包分发；不得把它们当作客户机证据。执行时核对实际工具版本、公开说明和当前数据流；无法核实时跳过该工具专属分支，继续完成可核实的系统、代理与浏览器检查。历史研究不代表当前线上版本或客户 Windows／Mac 实测，也不提供端点持续可用性保证。

## 如何解读

1. 优先核实可复现的事实：是否意外显示真实公网 IP，DNS 请求路径是否符合预期，Claude 网页是否可达，终端出口是否另有路径。按“实际泄露或连接故障 → 路径不明待复核 → 仅语言/时区/字体/Emoji 提示”排序，不按总分高低决定修改顺序。
2. 语言、时区、字体和 Emoji 是设备/浏览器特征；检测站对它们的扣分属于其自行设定的启发式评分。IPPure 关于 Claude 内部遥测或封号因果的说法不是 Anthropic 官方证据，不作为修改系统的依据。
3. 尽力降低可控风险，不能保证100%不封号；参考分不是官方风控规则或封号概率。高分不证明账号合规，低分也不等于账号会被封。WebRTC/DNS 警告要结合浏览器权限、TUN、代理规则与复测解释。
4. 修改确有问题的设置后，在同一目标设备、浏览器配置、工具/规则版本及已授权范围内复测受影响项，记录前后读数、来源覆盖和剩余未知，再验证原故障客户端的实际功能。Clearpath 的卡片重试可能重跑整组网络检测，执行前核对范围；无需为此重测无关本机项。不要为了“刷分”自动删除系统字体、伪装身份、改虚假地区或关闭无关安全功能。
5. 网页只测试它所在的浏览器；Claude Code CLI、Desktop、MCP 和远端进程的路由、认证仍需单独验证。Windows 浏览器结果也不能证明 WSL 路径。连通性请求完成、登录有效、断线保护有效分别下结论，不能互相替代。

## 避免把提示当作泄露事实

- WebRTC 中的内网地址、链路本地地址或 mDNS 主机名，不自动等于真实公网 IP 泄露。公开地址需与已知且获授权取得的出口基线核对；没有可靠基线时记为“公网候选路径待确认”，不要为取得基线擅自关闭 VPN。
- 检测页显示某地 DNS 解析器，不能单独证明请求绕过代理。结合客户端 DNS/DoH 设置、实际生效规则和检测能力判断；缺少路径证据时标为待验证，不因 DNS 地址或地理标签直接下结论。
- 故障时检测页打不开，记录“探测失败/未取得结果”，不能记录“未泄露”。可支持的结论限于有有效监测的观察窗口；不能外推到休眠、重启或未测客户端。
