## 必须保留的差异，不能平均成一条建议

| 差异 | 保存方式 |
| --- | --- |
| IPv6关闭 vs 正常统一双栈出口 | S03第1页和第4页手机表均保留；我方既有IPv4-only默认属于用户选择，另列双栈可选路线与目标证据 |
| IPv4偏好 vs IPv6阻断 | Microsoft兼容性建议与严格IPv4-only目标分开，不能用0x20冒充关闭 |
| Guardian原CLI优先 vs env前两周仅Desktop | 各自来源、时间、条件和效果证据并列，不强行合并 |
| Free3天/Pro15天 vs 半月/一月 vs Max两周约3次触顶 | 保留数字和原场景，标作者经验，不建立“过门槛就安全”的因果 |
| 固定节点 vs 官网自动择优 | 保留我方默认，网站作为可选设计；换传输通道是否换公网出口另核 |
| 隐私变量主动关闭 vs 只继承原值 | env-cleanup六变量与suyuan三变量保留法分开，不互相替代 |
| 主动暂停/彻底退出 vs 崩溃/通道故障 | 前者可恢复直连，后者声称维持隔离；按事件分别写验收 |
| PF旧报告部分失败 vs 项目后来已验收 | 按日期/设备/版本分别保留；旧报告移出当前目录不等于撤回，项目状态更新不等于新增测量 |
| 官网“始终隐藏” vs 条款暴露窗口 | 约2～5秒开机窗口、暂停、待开通例外跟随宣传同时呈现 |
| 官网“不记录内容” vs 长期保存真实IP | 按数据字段与保留期表达，不能归纳成纯本地或零日志 |

## 后续更新方式

用户只问某个机制时读取相关方法及直接依据；要求“全部”时才遍历以上对应来源组。新增来源先确定版本和文件/页面清单，实际读正文、关联实现、恢复分支及相关附件；遇到截断补读，未读直接标明。每项写清原方法、适用条件、证据、我方采用方式和目标验证状态，避免再次用“没官方证据”代替学习原方法。

新增来源或取得外部实现后继续按实际范围补读；已读来源仅在版本/兼容性或新证据需要时复核，不因为收录就自动运行。对外报告不继承第三方 `pass/established`，不把静态文档校验、官网发布清单或一次检测说成持续保护证明。
