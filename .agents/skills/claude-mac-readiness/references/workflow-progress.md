# 中断后继续：私有进度与离线说明

适用于等待客户确认／认证、确需重启或暂时中断。Mac 与 Windows 使用同一离线工具；参数由 Codex 填写，客户不用编辑 JSON。执行顺序仍以 [五步流程](five-step-setup.md) 为准。

## 保存当前步骤

```text
python <Skill>/scripts/claude_setup.py workflow-save --config <当前准确配置> --scope-file <本轮范围说明.md> --target-alias <本机别名> --platform <macos或windows> --stage <prepare或confirm或configure或verify或deliver> --next-step <准确下一步> --mode automatic --waiting-for <none或customer或authentication或restart> --artifact <本轮材料文件> --out <新私有进度目录>
```

`--scope-file` 必需，由 Codex 在客户本机准备本轮范围说明，不让客户填写模板。记录实际产品／入口用途、必须保留的业务、当前指定节点、系统语言等保留项、本轮必需／后续验收，以及仍待确认的问题；未知就明确写未知，不猜选或默认扩围。只记录必要的私有上下文，不写节点凭据。工具绑定该文件的路径与SHA-256，作为上下文而非操作授权。

`--artifact` 可重复，用于绑定已准备的候选、计划、恢复依据和核验材料；需要绑定哪些明确文件就逐个指定，不递归打包用户目录。保存当前配置与材料摘要、阶段和下一步，并生成客户本机可离线打开的 `继续配置.md` 与 `材料索引.private.md`，两份材料首先指向本轮范围说明，方便新会话复用已知目标与保留项。`--next-step` 仅填写不超过160字的安全简短说明，不含路径、URL或命令；详细操作步骤写入独立离线说明，再作为 `--artifact` 纳入材料。这是私有工作记录，可能含路径，不能上传 Git／共享盘、贴进公开聊天或转发另一客户；原始配置和凭据继续受原有私有目录保护。

阶段与五步对应：`prepare` 准备、`confirm` 待具体方案确认、`configure` 配置网络、`verify` 实际 AI 验证、`deliver` 交付。等待类型只是记录当前卡点，不表示客户已经同意或完成操作。系统语言与其他保留项继续有效。

重启或可能断网前，把已经准备并核对可用的**真实离线恢复说明**用 `--artifact <本机恢复说明.md>` 纳入本轮材料；`材料索引.private.md` 供离线找到原配置、备份和恢复说明。恢复说明必须有该设备可执行的原配置／选择状态／设置恢复动作，不能只写“运行 workflow-resume”或只给在线链接。

需要手动重启时，在独立离线恢复说明中写明实际软件／选择项、具体动作、可能失联、原配置恢复方法，以及恢复后要核对的活动配置／DNS／IPv6／路径；通过 `--artifact` 纳入材料。`--next-step` 只留例如“等待客户按离线说明重启并回复恢复”的简短描述，不塞入详细路径、命令或恢复步骤。**只有确认需要该动作后**才给客户安排时机，不为了填满生命周期报告要求重启。

## 恢复前先核对

```text
python <Skill>/scripts/claude_setup.py workflow-resume --config <当前读回配置> --checkpoint <原私有进度目录> --target-alias <同一别名> --platform <同一平台> --out <新继续核对目录>
```

恢复会话先读已绑定的本轮范围说明，复用已知用途、节点与保留业务，避免重复提问或默认扩大范围。范围说明改变／缺失时，恢复结果保持未完成，重新核对实际范围；不能仅改摘要续用。工具只核对本机身份、目标、平台、配置和指定材料是否仍匹配，并给下一步；不会应用候选、执行保存的动作、启动软件或联网。材料缺失／变化、配置漂移或目标不符时保留未完成，先审阅差异和客户后续修改，重新准备适用方案，不重放历史步骤。

即使材料匹配，也必须重新读回活动配置、节点、DNS、精确接口 IPv6 和控制通道状态，按仍有效的批准范围做非 AI 验证并生成新 `dns-ready`，之后才继续 AI 请求。保存的确认、旧成功报告和记录时间不恢复新操作权限或 DNS 新鲜结论；仍有效的同一具体批准也不因恢复会话而重复问。

客户只看“已完成／未完成、当前等待什么、下一步做什么”。私有细节与恢复材料留本机。工具保存／读回成功不能证明客户机网络已配置，也不能证明断线恢复成功。
