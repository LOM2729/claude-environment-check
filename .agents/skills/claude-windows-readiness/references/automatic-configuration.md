# 自动配置模式：一次确认后连续执行

**v0.8 顺序补充优先适用：** 自动模式采用 [国内视频 UDP 与国内域名](domestic-video-udp.md) 的 domestic-v4。先检查全局 UDP 限制层级；AI 保护优先，视频直连在其余 UDP 拒绝前，普通国内域名在拒绝后。旧 unified-v4 示例仅兼容旧策略；本轮 ai-route / ai-audit / baseline 明确使用 --policy domestic-v4。小火箭不可直接套用此 Mihomo 配置。

需要重启代理客户端/核心/服务或机器时，由客户手动操作；可能中断当前 Codex/远控通道的网络动作或影响不明的重载也交给客户。先保存进度和离线恢复说明，等待客户恢复连接后重新核验，不能自行断开通道；集中批准不替代人工交接。 具体按 [客户手动重启与恢复](five-step-setup.md#客户手动重启与恢复) 执行。

首先按 [五步顺序](five-step-setup.md) 执行，默认 [统一代理与关闭 IPv6](unified-ipv4.md)。同一具体方案一次确认，参数由 Codex 填写。

用户明确说“自动配置”“一键配置”“除了系统语言，其余帮我配好”时使用此模式。它是 **Codex 按检查结果编排实际工具的工作流**，不是独立安装器，也没有新增能跨所有客户端直接写配置的 apply 脚本。能否操作界面取决于客户机工具；不能把生成候选当作应用完成。

## 本模式的固定边界

1. **系统显示语言不改。** Windows 显示语言、macOS 全局首选语言、输入法及键盘布局均保留。不得为了改浏览器菜单语言间接修改全机语言。其他明确的客户保留项同样锁定。
2. **只确认一次具体批量方案。** 先做只读基线与必要候选，逐项列明内容，但集中询问一次。客户批准后，按顺序连续备份、配置、读回、复测；不再每个开关停下来问。已获批的同一具体清单也不重新确认。
3. **自动配置不等于把开关全部打开或关闭。** 对当前正常且符合目标的项目保留并核验；需要调整的才写入。目标或关键依据缺失时保留未完成，不编造设置值。
4. **原有订阅与规则是基线。** 保留节点资源、订阅更新机制、当前国内直连／国外代理或其他已明确分流选择、TCP／UDP约束，以及企业 VPN／LAN／远控所需例外；不整份替换成陌生模板。
5. **身份与控制能力由客户提供。** 登录、验证码、管理员认证和新增敏感权限由客户在本机处理。不能绕过被拒绝的权限。故意断网、重启机器或停止唯一远控通道需要独立确认和可执行恢复办法。

上述批量确认方式优先于其他参考文件中逐项询问的频率要求；备份、保护范围、实际验证和来源边界继续有效。客户要求恢复逐项确认时立即切回普通模式。

## 可自动检查并纳入方案的项目

| 项目 | 自动配置的处理方式 |
| --- | --- |
| 订阅／配置文件 | 检查实际文件类型、当前 profile、节点／组引用及扩展来源；有必要时准备最小候选，保留更新后持续生效的覆写方式 |
| TUN／系统代理／端口 | 按客户实际客户端及目标选择接管方式；方案写清实际端口、进程与覆盖范围，不机械同时开所有开关 |
| 国内外／应用分流 | 默认按 [统一出口](unified-ipv4.md) 将 AI 与普通国外代理流量绑定同一节点；DIRECT 例外先分类，国内及批准的本地例外保留。缺少具体节点等关键目标才补问 |
| DNS／DoH | 检查系统、核心、浏览器和节点解析的责任层及冲突；列出拟修改的具体层与解析器，不统一套某个公共 DNS |
| TYPE64／65、DNS64 | 核对当前支持和必要性；只有实际问题或明确目标要求时提出限定处理，不能以“一键”自动全部过滤 |
| TCP／UDP／QUIC | 保留已约定限制，检查规则及回退；节点不支持 UDP 不等于全机禁止 UDP，不擅自放行或全局阻断代理自身必要传输 |
| IPv4／IPv6 | 核对实际路径与既有策略；默认关闭精确联网接口、核心/DNS与节点外层的 IPv6；必要依赖先处理兼容并保留未完成，不以优先 IPv4 冒充关闭 |
| WebRTC／STUN | 检查实际浏览器策略和媒体需求；必要调整写明对通话／共享的影响，不安装不明扩展或伪造检测结果 |
| Claude Desktop／Code／浏览器 | 检查实际安装、启动入口、认证来源和代理采用；修复已证实的路径冲突，不读取或回显凭据 |
| 自启／重载 | 使用当前软件支持的持久化入口，写清保存／重载副作用；需要安装服务、关闭进程或影响远控时单列影响 |
| 时钟／时区 | 核对时间准确性；时区仅按客户已给目标调整，没给目标就保留，不从节点出口推定所在地 |
| 浏览器语言／系统地区 | 可检查；客户已给出明确目标且软件支持限定修改时纳入方案，否则保留现状。系统显示语言始终排除 |

客户没有节点或可用配置时，先完成可做的检查并说明缺口，不默认购买代理或注册账号。仅有文件但没有目标设备访问时，只能准备候选与清单。

## 执行顺序

1. **识别目标与工具。** 确认真实执行端、Mac／Windows、客户端／代理版本及可用终端／界面工具。Windows 与 WSL 分开。复用已知信息，只补影响具体方案的关键缺口，不逐个向客户讲解所有技术开关。
2. **采集基线。** 使用 `collect`、实际应用只读界面与必要静态配置检查。输出系统语言及其他保护项的当前摘要，标记本次保持。需要的外部测试不能默认为获准。
3. **准备完整方案。** 统一分流先按 [统一规则流程](unified-ipv4.md) 用 `ai-route` 生成候选及私有计划；具体节点未确定不能猜选。 可用 `plan` 生成配置候选、私有快照与差异。列出下表，已正常项标“保留并核验”，阻塞项说明下一步；只将当前已确定且受支持的动作纳入待批准执行清单。
4. **集中确认一次。** 同一次确认可覆盖明确列出的配置动作、备份、已确认不影响控制通道的热重载和指定站点的基线／复测。检测站点、数据流、可能中断以及恢复办法要清楚，不能只写“同意全部”。关键事实未知而无法形成准确方案的动作暂不纳入。
5. **连续执行并遵守依赖。** DNS/代理配置与时区、语言等独立本机项目可并行；不要同时写同一文件或争用重载。先完成 DNS/代理配置、读回和非 AI 目标路径核验，按 [阶段门槛](lifecycle-checks.md) 记录本轮证据，之后才发起 Claude/OpenAI 服务请求，包括 DNS 查询。不要为了修改前对比先访问 AI。 客户批准后，紧邻写入前核对配置未变化，备份、执行一个必要改动、读回并做相应验证，再继续下一项。能由 Codex 完成的持续完成，不以解释步骤代替操作。缺少界面能力时，只把必要点击交给客户，再继续核验。重启代理及可能断开控制通道的动作始终按人工交接规则处理。
6. **处理偏差。** 新问题需要改变目标值／作用范围、追加安装、换节点、清数据、降级 TLS 或更改防火墙时，暂停该项并解释新方案；原批准不延伸到新动作。失败或保存结果未知时先查证，不盲目重复。对其他独立且已批准项可继续执行。
7. **完成交付。** 使用 `verify` 核对真实读回，另核验应用载入、实际客户端与约定网络路径；根据真实结果填写 review，再生成已完成／未完成报告。批量批准覆盖的条目可以分别记录 `approved`，但不能据此自动把 `verified` 填为 true。核验 JSON 只记录事实，不授予后续动作权限。

## 给客户看的方案

> 本次使用自动配置模式，系统语言保持不变。以下是准备处理的项目；你确认后，我会连续完成配置和验证，正常情况下不再逐项询问。

| 项目 | 当前 → 目标／保留 | 为什么需要 | 影响及恢复 | 改后验证 |
| --- | --- | --- | --- | --- |
| 按实际已读到的信息填写 | 不使用猜测值 | 对应客户需求或已观察问题 | 写明具体可恢复方法 | 可观察的完成条件 |

> 同时列出本轮对外检测的准确站点和数据范围。是否按这份方案执行？可回复“确认这份方案”，或指出需要保留／删除的项目。

不要先问“能不能检查”再逐项问一遍已批准的只读动作。不要把正常的软件读回、新建本地脱敏报告当作新一轮配置审批。客户已有明确批准的具体清单时，直接核对适用性后执行。

## 能力不足时的交付

“自动配置模式”说明任务交互方式，不保证任何版本／权限下零人工操作。报告具体写出已做与未做：系统语言保持、已配置项、已核验但无需改的项、仍需客户认证／点击的项、检测或恢复未覆盖项。不能用“缺工具”把全部任务交还客户，也不能为追求一键完成伪造验证结果。

## 配置完成后的持续使用

按 [生命周期检查](lifecycle-checks.md) 保存本机基线；本包流程完成订阅/客户端/核心更新后读取活动配置并运行 recheck。自动配置方案默认纳入适用的主动验证和启动前检查，先列出准确探测范围，按有效授权运行 network-check / preflight；实际启动另按客户请求或已批准方案加 --launch；具体已批准范围不重复询问。无响应记未完成，配置漂移先审阅，不自动恢复。没有安装常驻后台监控。
