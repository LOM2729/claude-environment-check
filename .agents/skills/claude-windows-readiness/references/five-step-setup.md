# 五步自动配置：默认快速路径

本文件是 Mac／Windows 配置的唯一顺序。普通任务默认快速路径，客户只经历“识别并出方案 → 确认后执行 → 集中复查和结果”。逐项模式沿用同一顺序，只改变确认方式；明确要求深度体检或实际故障需要时，再展开相关参考。

## 快速路径（普通配置默认）

只处理本轮设备、代理及实际使用的入口；一次读取现状，合成一份最终候选，一次具体确认，执行后集中核验。正常项保留；同一配置、网络、入口及观察时段的有效证据复用，仅变化、失败或未解决问题触发相关重查。没有新证据时不循环导出、导入、测速或重启。

默认只留必要配置、差异、恢复说明和简短实测记录。完整 review／HTML 面板仅在用户要求或交付确实需要时生成；不为填满 19 项清单展开无关模块。只有实际中断、换会话或等待可能断线的人工操作时才使用 workflow-save。账号／支付、VM／VPS、历史教程、第三方评分和故障演练按需展开，不作为每次配置的必做项。

必要原值与备份、隐含请求检查、必保业务、配置读回、DNS／代理前置核验和真实功能验证仍保留。只收到文件或在服务者本机时，结果限于离线候选，不能称客户机已生效。缺基础网络、配置、权限或客户端支持时，说明具体阻塞和下一步，不用重复检查掩盖问题；不承诺固定完成分钟数。

## 1. 准备：一次读取并做好最终方案

- 只读核对目标设备／执行端、实际使用的产品入口、客户端／核心版本、活动配置、指定节点、端口、接口及依赖。Windows 原生、WSL、VM、远端分别记录。已知不问；只补无法读取的用途、缺失节点／配置、必保业务和具体时区目标，不让客户选择 DNS 参数或填 JSON。
- 默认 `domestic-v4`：沿用指定节点及原有业务，Claude 专属组与基础组同节点，AI 保护优先且失败不回落 DIRECT；精确联网接口及代理层 IPv6 关闭。保留全部教程扩展目标／关键词／IP／ASN、连接设置、IPv6 与既有非 AI 拒绝规则；国内视频直连在其余 UDP 拒绝前，普通国内直连、普通国外统一代理。用户已明确的 UDP／业务例外优先，不为缩短流程删规则。
- 系统语言、输入法和键盘保留；完整配置按 [时区策略](timezone-policy.md) 提出指定稳定出口的具体城市／系统时区 ID，原值、自动选项及恢复纳入方案。目标不清先补问；局部任务和明确保留项按用户范围处理，浏览器语言无目标保留。
- 对当前与最终候选做 `contact-scan`，检查测速／health-check、provider、资源下载、脚本、DNS 引导与节点依赖，另核对 GUI 隐含测试和自动刷新。`direct-review` 分类直连例外，`udp-check` 加本机证据确认全局限制层；先处理 IPv6／企业网／会议／视频／游戏／远控等依赖冲突，不静默丢弃例外。
- 复用已有运行时与版本适配的生成器：按 [连接设置](connection-reuse.md) 准备适配，`ai-route --policy domestic-v4` 合成最终候选，再做相关审阅与全量私有差异。Mihomo 用 YAML／JSON，小火箭按 [原生适配](shadowrocket-domestic.md) 生成 `.conf`，不写私有数据库或编译规则。后改 DNS／URL 等字段时重生成受影响审阅，不篡改旧快照。工具参数按当前随包版本的 [说明](automation.md) 填写。
- 保存将修改对象的原值、可用备份、选择状态、相关扩展、精确接口身份和可执行恢复方法；正文与证据只留本机，保护之后的用户修改。缺 Python／YAML 且无法准备候选时，只将必要依赖及来源单独预览批准，完成后回到最终方案；不改系统 Python／执行策略。

配置满足前不运行可能联网的校验、安装、AI CLI 诊断、AI DNS 查询或浏览器启动／重启／恢复标签。盘点现有进程、自启和恢复会话，保护正在运行的 Codex／远控，不自动终止。其他会话确需退出或新增安装时写入方案；在线 Codex 的首次联网依赖已有基础通道。

## 2. 确认：一份具体方案，一次批准

简短列清沿用项、原值到目标、影响、备份／恢复和核验方式。包括指定节点、DIRECT／UDP 业务例外、IPv6 精确接口、DNS 引导、目标时区、必要安装／保存／重载，以及准确非 AI 检测站点、传出数据和实际 AI 验证范围。先备齐最终候选与恢复材料再询问，不先泛问权限、批准后才补方案。

同一具体清单已有有效批准就连续执行，不逐开关重复问。新增范围或改变方案时才补充说明。密码、验证码和系统认证由客户处理；集中批准不允许自行中断控制通道。

## 3. 配置网络：应用后集中核验

1. 紧邻应用复核输入未变，运行新的 `action-check --action proxy-load` 检查隐含请求和依赖，按支持的持久化入口应用已批准候选。读回活动配置、实际组／节点、Rule 模式和系统代理／TUN；用 `verify`、`ai-audit --policy domestic-v4`、`tutorial-check` 核对相关静态结果，不把文件匹配当进程采用。
2. 按批准的精确接口处理 IPv6，`ipv6-check` 取得实际状态；系统、核心／DNS和节点外层分开看，依赖冲突或证据不足保留未完成。核对 UDP 限制层及本轮业务例外，超时不证明阻断。
3. 使用已批准 bootstrap 非 AI 目标验证 DNS、实际代理路径和本轮国内／国外分流；结合运行规则与连接链，不用 Fake-IP、同一端口或一次失败代替路径证据。需要调整时只重查受影响部分。
4. 真实读回、路径证据及精确接口状态满足后生成本轮 `dns-ready`；它绑定当前配置、入口和 DNS／IPv6 状态，不提供额外授权。此门槛通过后才允许 AI 请求，包括 DNS 查询。

### 客户手动重启与恢复

只有实际需要重启或操作可能影响 Codex／远控时才交接；影响不明同样交客户。先按 [进度与恢复](workflow-progress.md) 准备必需范围文件、保存材料和离线恢复方法，再给具体动作、影响与操作时机。代理／核心／服务／机器重启由客户手动完成，不用后台任务或杀进程代替。

等客户恢复后用 `workflow-resume` 核对材料和变化，重新读回活动配置、节点、DNS、精确接口 IPv6，并做批准范围的非 AI 验证及新的 `dns-ready`。时间经过、PID 或客户一句“好了”不能代替实际核验；同一仍有效批准不重复问。恢复失败按原值与 [分层恢复](recovery-and-acceptance.md) 处理，不盲目重导入、重启或覆盖客户后续修改。

## 4. 使用 AI：每个实际入口验证一次正常功能

网络门槛通过后才按批准范围安装／更新、打开／激活应用、登录或运行诊断；紧邻实际动作运行对应新的 `action-check`。需要 `preflight --launch` 时按 [生命周期工具](lifecycle-checks.md) 使用，不添加常驻守护。状态或依赖改变后重查受影响部分，旧进程不一定采用新代理环境。

验证每个本轮实际使用入口的认证来源、指定代理路径和一次正常功能请求；网页、Desktop、CLI、后台与远端不互相代证。不启动客户不用的客户端，不默认测试附件、Artifacts、MCP 等额外功能。未成功时先定位具体阻塞，无新证据不循环重试；需扩大排障时说明原因和下一步。登录／验证码由客户处理。

## 5. 交付：简短结果，通过即结束

只列本轮完成项、未完成的具体原因和一个下一步，保留必要私有记录及恢复材料。没有变化或未解决风险时不重复测试、导出或重做报告。正式报告按需使用 `review-template --mode automatic`，由 Codex 按真实结果填写，未测项不能标完成，客户不编辑 JSON。

默认只验收当前正常使用；更新、重启、唤醒、换网及故障恢复等未实测事件留后续复查，不主动制造事件。用户明确选择的事件按 [逐事件验收](recovery-and-acceptance.md) 纳入必需项，已有记录不降级。普通连续操作不强制生成交付检查点，实际需要中断／换会话才保存进度；下次先查变化，不从头重装或恢复旧授权。本包不提供常驻监控、系统 Kill Switch 或账号安全保证。
