# 五步自动配置：唯一执行顺序

本文件是 Mac／Windows 配置任务的唯一操作顺序。其他参考是按需核对模块，长清单不是第二条流程；旧八章仅在客户明确请求时展开。自动模式集中确认具体方案，逐项模式沿用相同顺序、按具体项目确认；既有明确批准不重复询问。

默认 `domestic-v4`：国内及已确认本地例外直连，普通国外与 Claude／OpenAI 共用指定节点；Claude 专属组与基础组同节点，AI 保护优先且失败不回落 DIRECT；选定联网接口及代理层 IPv6 关闭。保留 IPv6 拒绝规则及既有非 AI 拒绝、国内视频直连在其余 UDP 拒绝前、普通国内域名、完整教程扩展与连接设置。系统语言、输入法和键盘保持；时区及浏览器语言未明确目标就保留。

## 1. 准备：完整方案先做好

**只读识别，不提前打开 AI。** 核实真实执行机与客户机、Mac／Windows 原生环境、实际客户端和代理版本、活动配置与来源、节点选择、入口端口、接口及 Python／依赖。Windows 原生、WSL、VM、远端分别记录。仅文件、PATH 和安装元数据等确定离线检查可先做，不运行可能联网的 AI CLI、doctor、auth、更新或安装命令。

复用上下文，开场最多补三组确实缺失的信息：

1. **实际用途**：要用 Claude／Codex 的网页、桌面端、CLI 或其他入口；只问本轮需要的。
2. **已有配置与节点**：沿用读到的有效配置、现有节点和明确选择；确实缺文件或有多个无法判定的目标才问。
3. **必保业务**：是否有必须保留的会议、视频、游戏、企业 VPN、局域网或远控；已知的不重复问。

把已知范围写入客户本机的“本轮范围说明.md”：实际产品／入口、必保业务、指定节点、系统语言等保留项、本轮必需／后续验收与未决问题；未知明确写未知。由 Codex 准备，客户不填模板，供新会话恢复上下文，不授予操作权限。

系统版本、路径、端口自己读，不向新手追问 TYPE65、解析器或代理技术参数。没有明确时区／浏览器语言目标就记录保留，不能从出口地区推定。客户未提供可用配置或无法进入目标机时，先完成离线审查，说明当前能力边界。

**以下检查、候选与恢复准备全部在批准前完成：**

- 盘点现有 AI 进程、浏览器恢复标签、自启、订阅自动刷新及安装完成后启动项；保护当前 Codex／远控，不自动杀掉或断开。
- 对当前与候选配置运行 `contact-scan`；离线检查测速、url-test／fallback、health-check、provider、资源下载、脚本、DNS 引导与节点依赖。GUI 的额外测速与 AI 解锁检测另核对。发现 AI／未知隐含请求时先在候选中准备处理，不运行会联网的校验或启用。
- 用 `direct-review` 分类非显然直连；用 `udp-check` 加本机只读证据确认全局 UDP 限制位置；核对企业网、会议／视频／游戏／远控及 IPv6、DNS 依赖。冲突不静默丢弃，不用“全局放行”掩盖。
- 优先复用已有运行时。确实缺 Python／PyYAML 而无法离线准备完整候选时，只将明确依赖安装范围、来源及影响作为独立前置方案确认；完成后回到准备步骤，再给最终配置方案。前置安装批准不能覆盖未知配置改动。正常条件仍一次具体配置确认，不承诺缺工具也绝对只问一次；使用任务虚拟环境，不改系统 Python 或执行策略。
- 按实际版本准备 [连接设置](connection-reuse.md) 与 [完整教程覆盖](tutorial-coverage.md)，最终用 `ai-route --policy domestic-v4` 生成完整候选。Mihomo 用 YAML／JSON；小火箭用 [原生 .conf](shadowrocket-domestic.md)。若之后再改 DNS、URL 等，重新生成相关审阅、候选和差异，再扫描，不能改旧快照凑审计。
- 以原活动配置到最终候选准备完整私有差异与备份；保留生成器实际输入供规则审计。保存选择状态、相关扩展、系统设置原值、精确接口身份及可执行恢复步骤。文本事务按 [可靠回滚](recovery-and-acceptance.md)，原生应用与系统设置分层备份。未识别的写入者／自动加载或控制通道风险，先留未完成，不擅自停止核心。

用 `review-template --mode automatic` 记录系统语言与明确保留项；需要保留其他任务可重复 `--preserve <TASK_ID>`。客户不编辑 JSON。可以准备聊天摘要，初期不为展示离线 HTML 提前启动浏览器。

## 2. 确认：一份具体方案，一次批准

客户只需看：**沿用什么、具体改什么、影响什么、如何恢复、怎样核验。** 完整候选和恢复材料已准备好，再集中确认；不要先泛问“能不能配置”，批准后才开始找问题、补候选。

方案包含指定节点、DIRECT 保留业务、UDP 层级与视频例外、IPv6 精确接口范围、DNS 引导、必要依赖／应用动作、已核实的保存或重载行为，以及非 AI 检测和后续实际 AI 验证的准确站点／数据范围。本次生命周期默认仅正常使用为必需；若客户明确选择更新、重启、换网或故障事件，另列实际动作、影响与恢复。

自动模式批准后连续完成同一具体清单，不再逐开关询问。新增目标、扩大范围或改变方案时才补充预览。登录和系统认证由客户处理；新安装、敏感权限及可能断开通道的动作按实际影响处理，集中批准不允许自行中断控制通道。

## 3. 配置网络：执行已批准候选，先验证非 AI

1. 紧邻导入／重载先运行新的 `action-check --action proxy-load`，并复核目标配置未变、隐含请求和控制通道风险仍与批准方案一致；通过后按支持的持久化入口应用候选，读回最终运行配置、实际组／节点、模式、系统代理／TUN。`verify`、`ai-audit --policy domestic-v4` 与 `tutorial-check` 分别核对文件和策略，不把静态结果当运行采用。小火箭不写私有数据库或编译规则。
2. 按精确接口方案处理 IPv6 并读回；`ipv6-check` 验证选定接口关闭，代理 DNS／核心／节点外层另验。遇到企业网或节点依赖 IPv6，先按批准兼容方案处理；证据不足不冒充关闭。
3. 只用批准的 bootstrap 非 AI 目标核验 DNS、实际代理路径、国内／国外分流、必要业务与 UDP。不能用 Fake-IP、同一端口或一次超时代替路径证据。新的隐含请求或保存／重载影响与预期不同则暂停相关项。
4. 记录真实读回与路径证据，生成当前 `dns-ready`。它绑定当前配置、入口、DNS 和精确接口状态，不是自动路径证明或联网授权。记录未满足前，不发 Claude／OpenAI 请求，包括 AI DNS 查询。

```text
python <Skill>/scripts/claude_setup.py action-check --action proxy-load --config <最终候选> --out <新目录>
python <Skill>/scripts/claude_setup.py ipv6-check --interface <实际服务或适配器> --out <新目录>
python <Skill>/scripts/claude_setup.py dns-ready --config <活动配置读回> --proxy <已核验HTTP入口> --ipv6-interface <同一接口> --readback-verified --dns-path-verified --proxy-path-verified --evidence <真实脱敏证据> --output <新记录.json>
```

参数由 Codex 填写，多个接口重复参数。`action-check` 只检查不执行。只有确认不会影响控制通道的热重载可在已批准范围执行；需要重启或影响不明时按下面交接。

### 客户手动重启与恢复

**只有实际需要时才提出重启。** 先核实软件提示、保存行为和副作用，不为了凑验收反复重启。

1. 用 [workflow-save](workflow-progress.md) 的必需 `--scope-file <本轮范围说明.md>` 绑定当前用途与保留项，保存阶段、下一步、候选／差异／恢复材料摘要与本机离线说明；备份和凭据不贴聊天。
2. 给客户明确动作，例如“在某客户端选择某配置后退出并重新打开”，说明可能断线、失败时如何恢复，再询问方便操作的时机。代理／核心／服务／机器重启，以及可能影响 Codex／远控的 TUN、网卡和系统代理动作由客户手动操作，不用定时任务、杀进程或后台脚本代替。
3. 等客户完成并回复恢复。未回复、时间经过、PID 出现都不是恢复证据；相关项保持未完成，可继续独立本地工作。
4. 用 `workflow-resume` 核对保存材料，先读已绑定的本轮范围说明；范围改变／缺失则保留未完成并重新核对，不重问已知或默认扩围。再重新读回活动配置、节点、DNS、精确接口 IPv6 并做已批准非 AI 验证，重新生成 `dns-ready` 后继续。保存记录不恢复操作授权，同一仍有效批准不重复问。
5. 恢复失败就按离线说明恢复原配置／选择／设置并复核；保护后续修改，不盲目重导入或连续重启。

## 4. 使用 AI：只验证实际需要的入口

当前网络门槛通过后，再按批准范围安装／更新、打开网页、启动／激活应用、重启浏览器／恢复标签和登录。下载与诊断本身也可能请求 AI 域名，不能前置。紧邻实际动作运行新的 `action-check`；`preflight --launch` 仅在明确启动请求或已批准动作中使用，不安装常驻守护。

```text
python <Skill>/scripts/claude_setup.py action-check --action <实际动作> --config <当前配置> --proxy <同一入口> --dns-ready <本轮记录> --out <新目录>
```

支持的动作类型按 [生命周期工具](lifecycle-checks.md)。若记录涉及浏览器偏好，传相同偏好文件。网络、配置、版本或入口变化后先重查受影响依赖；已运行进程未必读取后改的代理变量，必要重建应在批准范围且不切断通道。

分别验证实际客户端的认证来源、功能请求、指定代理与必要的 DNS／UDP／IPv6 观察。网页、桌面端、CLI、后台、WSL／远端不能互相代证；不强制启动客户不用的客户端。实际请求与探针结果分别记，登录／验证码由客户本人处理。

## 5. 交付：简短结果，可继续

客户只看本次必需项的已完成／未完成摘要，未完成说明具体原因和一个下一步；详细清单、差异、证据、配置与恢复材料留客户私有目录。

[lifecycle-template](recovery-and-acceptance.md) 默认仅 `normal_use` 为本次必需，其他七类事件列“后续复查”，未实测仍是未完成，不影响本次必需完成数。明确选择的本轮事件用 `--required-event` 严格验收，旧全必需记录不降级；不能因为正常使用通过就声称重启、换网或故障保护通过。

用 `workflow-save` 保存交付或中断点；下次恢复先核对材料变化、重验当前网络，不重放历史操作或从头重装。没有真实导入／运行／故障证据的项目保留未完成。本包没有常驻监控、系统 Kill Switch 或账号安全保证。
