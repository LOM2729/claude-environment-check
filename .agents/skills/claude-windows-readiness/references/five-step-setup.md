# 五步配置：默认快速路径

仅首次或完整配置默认读本页。诊断、清理及其他局部任务从 [专题入口](workflow-methods.md) 进入；纯资料不采集或探测，离线任务不强迫重配网络。普通配置只覆盖实际入口，复用有效证据，技术细节在需要时读对应模块。

## 1. 准备：读取现状并形成候选

- 确认目标设备、实际客户端、代理版本与活动配置、指定节点、端口、接口、依赖及必保业务；Windows 原生、WSL、VM、远端分别判断。已知不问，只补无法读取且影响结果的缺口，不让客户填 JSON。
- 默认 `domestic-v4`：Claude 专属组与基础组同一指定稳定节点，AI 保护优先且失败不回落 DIRECT；关闭选定联网接口及代理层 IPv6。保留已有 IPv6／非 AI 拒绝、教程扩展目标／关键词／IP／ASN 与连接设置。国内视频直连位于其余 UDP 拒绝前，普通国内直连、普通国外统一代理；用户已确认的业务例外优先。具体规则按需读 [统一出口](unified-ipv4.md)、[UDP与国内业务](domestic-video-udp.md)、[服务路径](service-routing-checks.md)、[教程覆盖](tutorial-coverage.md)及 [连接设置](connection-reuse.md)。
- 保留系统语言、输入法和键盘。完整配置按 [时区策略](timezone-policy.md) 提出稳定出口对应城市／时区 ID，保存原值及自动选项；目标不清才补问，局部任务和明确保留项优先，浏览器语言无目标保留。
- 对当前与最终候选做 `contact-scan`、`direct-review`、`udp-check`，核对隐含测速／health-check、provider／资源刷新、DNS 引导、节点与控制通道依赖，先解决企业网／会议／视频等冲突。按当前 [工具说明](automation.md) 用 `ai-route --policy domestic-v4` 生成候选，准备完整私有差异、原值、备份与可用恢复。缺必要运行时时先单独准备依赖方案，不改系统 Python／执行策略，不猜工具参数。
- Mihomo 使用适配的 YAML／JSON；小火箭按 [原生适配](shadowrocket-domestic.md) 生成 `.conf`，不写私有数据库。已有小火箭大量 DIRECT、旧组名或首页节点未导出时，按 [快速准备](automation.md#已有小火箭配置的快速准备) 在副本批量分类／显式迁移，未知例外不放行；核对配置列表活动勾选，编辑页不证明已采用。

网络条件满足前只做确定离线的检查，不启动可能联网的校验、安装、AI CLI 诊断、AI DNS 查询或浏览器启动／恢复标签。盘点隐含请求与现有会话，保护正在运行的 Codex／远控；首次联网仍需已有基础通道。只收到文件时交付候选，不报告客户机已生效。

## 2. 确认：一份具体方案

列清变更／保留项、原值到目标、影响、备份／恢复与验证，包含节点、DIRECT／UDP 例外、IPv6 精确接口、DNS、时区、必要安装／重载，以及外部检测的准确站点和传出数据。需要确认时一次确认；同一具体清单已获有效批准就执行，新增范围再说明。密码、验证码和系统认证由客户处理。逐项模式仅在用户明确选择时使用 [确认协议](change-confirmation.md)。

## 3. 执行：应用并读回

紧邻应用复核输入未变，用当前 `action-check --action proxy-load` 检查隐含请求，按持久化入口应用已批准候选。读回活动配置、实际组／节点、Rule 模式及系统代理／TUN；`verify`、`ai-audit --policy domestic-v4`、`tutorial-check` 只证明对应静态结果。按 [精确接口范围](unified-ipv4.md) 取得 `ipv6-check` 实际状态，系统、核心／DNS、节点外层分别核对；IPv4 偏好、AAAA 空或超时不证明阻断。

### 客户手动重启与恢复

仅实际需要重启代理／核心／服务／机器，或操作可能中断 Codex／远控时，按 [进度与恢复](workflow-progress.md) 保存私有材料和离线恢复说明，给出具体动作、影响和时机，由客户手动完成。恢复后 `workflow-resume` 核对变化，重新读回并核验当前网络，不恢复旧 DNS 结论或新授权。客户说“好了”只说明手动步骤已做，仍需读回；日志显示超时／撤销时保持未完成，不以一句答复替代验收。写入状态不明先对账；按 [分层恢复](recovery-and-acceptance.md) 保护后续修改，不盲目重试或覆盖。`recovery-*` 仅处理本轮精确批准的现存文本文件，不自动重载。

## 4. 核验：先非 AI 网络，再实际功能

1. 用已批准的 bootstrap 非 AI 目标验证 DNS、代理路径、国内／国外分流及 UDP 业务例外；结合实际连接链和配置，保留探针错误及采样范围；仅有HTTP错误、坏响应、超时或无候选不算阻断通过，Fake-IP和同一端口也不代证。满足当前精确接口 IPv6 与路径证据后生成本轮 `dns-ready`。当前工具门槛只支持 IPv4-only，双栈需另设方案与验收，不能伪造通过。
2. 门槛通过后，才按范围安装／更新、打开、登录或诊断；紧邻动作使用对应新的 `action-check`，启动需要时读 [生命周期工具](lifecycle-checks.md)。状态改变只重查受影响项。
3. 每个实际使用入口验证认证来源、指定路径和一次正常功能；网页、Desktop、CLI、后台与远端不互相代证。未成功就定位最小阻塞，不无证据循环重试；不默认展开附件、Artifacts、MCP 或客户不用的入口。需要客户在平时浏览器回报体检结果时，用 [自助问题卡](score-check.md#客户自助回报)，只收红黄项，不索取IP、账号或节点。

## 5. 交付：简短结果

列已完成、未完成的原因和下一步，保留必要私有证据与恢复材料。文件匹配、应用载入、进程采用和实际功能分别判断；没测不算通过。默认验收当前正常使用，更新／重启／换网／故障事件仅在本轮需要时按 [事件验收](recovery-and-acceptance.md) 展开，不为填表制造事件。正式 review／HTML 报告按需生成，实际中断才保存续接点。系统防护仅在明确选择时按 [专项工具](execution-capabilities.md)启用，配置与真实网络效果分别验收，不提供账号防封保证。
