# Clash／Mihomo 与小火箭：配置导入和分流

需要重启代理客户端/核心/服务或机器时，由客户手动操作；可能中断当前 Codex/远控通道的网络动作或影响不明的重载也交给客户。先保存进度和离线恢复说明，等待客户恢复连接后重新核验，不能自行断开通道；集中批准不替代人工交接。 见 [客户手动重启与恢复](five-step-setup.md#客户手动重启与恢复)。

自动配置顺序以 [五步流程](five-step-setup.md) 为准。网络及选定接口 IPv6 未核验前，不打开/安装/登录 AI，不运行未证明离线的 CLI 诊断，不重启浏览器恢复标签。代理校验/导入/启用/重载前先检查测速、health-check、资源下载及附加请求。纯本机时间/语言字段检查可并行。

目标是把客户提供的文件变成可核对、可回退的实际配置。先辨认格式，再操作；本文件的示例都是局部逻辑，不能当作完整可导入配置。未获得目标机访问时交付候选，并标记“尚未导入／未验证生效”。

## 1. 文件盘点与备份

| 收到的材料 | 如何处理 |
| --- | --- |
| 完整 Clash/Mihomo YAML | 检查 `proxies`／`proxy-providers`、组、规则、DNS、TUN 与扩展合并；确认当前客户端及核心支持 |
| 只有节点的订阅或分享 URI | 只说明节点资源，不能当作完整 DNS、分流和断线配置；密码、UUID、订阅 URL 不进入对话／报告 |
| 只有规则列表或 rules 扩展 | 核实它引用的出站组存在，按对应客户端扩展入口合并；不能作为完整 profile 启动 |
| Shadowrocket `.conf` | 核对 `[General]`、`[Proxy Group]`、`[Rule]` 等实际内容；节点列表／订阅可能仍单独管理 |
| 文件夹／压缩包 | 先只列目标配置和必要依赖；不执行附带脚本，不读取无关账号数据；识别主文件与重复版本 |

原件保留。记录当前活动配置标识、路径、哈希、客户端／核心版本、选中节点、模式和扩展来源；在客户本地私有目录备份，读回确认可用。含凭据的备份只留客户受控位置，不放公开 Git／第三方转换站。报告使用别名和脱敏差异。

修改前比较候选与原配置：不得丢弃已有企业 VPN、LAN、远控、用户自定义规则和注释；检查外部 providers、脚本、重写、MITM 证书和控制端口暴露。普通域名分流不需要安装解密 CA 或关闭 TLS 证书验证。异构客户端转换须逐项映射，不能改扩展名后直接导入，也不默认把私有订阅交给在线转换服务。

## 2. Clash Verge Rev／Mihomo 分支

1. 在“订阅／配置”页查看正在使用的 profile。完整本地文件通过“新建 → 本地配置／选择文件”或该版本支持的拖拽导入，另起可识别名称。官方说明导入会复制文件到 profiles，后续编辑原下载文件不等于编辑已加载副本。[导入文档](https://www.clashverge.dev/guide/profile.html)
2. 如果客户已有可用订阅，只需增补规则，优先使用该 profile 的“编辑规则”或受支持的扩展／覆写机制；先确认扩展是否被其他 profile 共享。不要修改一次性生成的运行配置，否则保存、重启或订阅刷新可能覆盖改动。[规则文档](https://www.clashverge.dev/guide/rules.html)
3. 在当前 profile／核心可用的检查入口验证配置，确认组名／provider 引用、节点协议、规则顺序、DNS／TUN 语法。若用核心 `-t -f` 检查，先核实该版本帮助和初始化是否会下载 provider／规则数据库；不是默认离线操作。YAML 可解析只证明格式，不证明核心接受或已生效。
4. 启用候选 profile，核对加载错误和运行配置中的目标规则，选择 `Claude` 组内的指定节点；需域名分流时核对路由为 Rule。Global／Direct 是路由模式，系统代理／TUN 是接管机制，两者分开记录。
5. 系统代理、TUN 和服务模式只按客户端需求及批准范围调整；不假定所有终端都使用系统代理，不把开 TUN 等同全局代理。核对实际监听端口，禁止沿用教程里的 7890 等固定值；服务安装／提权另依实际操作处理。
6. 在客户实际应用发起范围内请求，查看命中的规则及出站链，再看功能结果。确认自定义规则在配置保存、必要重载后仍在；订阅刷新、重启等会产生副作用的验证按批准范围执行，不把静态检查写成实测。

## 3. Shadowrocket 分支

1. 先区分“首页节点／订阅”和“配置文件”，备份两者必要信息。通过实际版本提供的“配置 → 导入”或文件共享入口导入 `.conf`，另存新名称，明确选中该配置。
2. 在配置旁的 `ⓘ → 代理分组` 核对／建立 `Claude` 组，类型 `select`，选择客户指定的现有节点。节点缺失时先补资源，不把组静默改成 DIRECT。代理组固定选择不能保证供应商出口永不变化。
3. 返回 `ⓘ → 规则`，按目标域名逐条建立 `DOMAIN-SUFFIX`，策略指向同名组；检查它前面的规则是否已抢先匹配。保留企业阻断与用户明确例外，不能为抢优先级无条件移到全部规则最前。
4. 核对当前活动配置、全局路由中的“配置”模式、组内节点、实际连接状态和请求记录。界面名称依版本现场读取；Windows 客户使用其实际客户端，不套用小火箭的 Apple 平台界面。
5. DNS、IPv6、STUN、UDP 不支持时的回退、包括所有网络、按需连接等放到各自检查项；导入 `.conf` 不一定覆盖应用级设置。配置包含脚本／HTTPS 解密时，先处理这些额外能力的必要性及影响。

入口和三域名做法来自 [EianLu 的原帖及四张配图](https://x.com/EianLu/status/2112096071023497521)，属于已核对的**个人操作示例**。参数补充可参考 [Shadowrocket 社区 Wiki](https://github.com/LOWERTOP/Shadowrocket/wiki)，以当前软件说明及目标机结果确认；不把社区资料标成软件厂商或 Anthropic 官方。

## 4. Claude 域名与规则示例

下列是原帖三条规则的逻辑，`Claude` 必须替换为实际存在且大小写一致的组名。Mihomo 将这些字符串加入既有 `rules` 序列；Shadowrocket 放入 `[Rule]`，两种完整文件格式不通用。

```text
DOMAIN-SUFFIX,claude.ai,Claude
DOMAIN-SUFFIX,claude.com,Claude
DOMAIN-SUFFIX,anthropic.com,Claude
```

三条覆盖相关后缀及子域，包括 `api.anthropic.com`；它们不是全部功能的永久域名清单。按实际用途查 [Claude Code 官方网络需求](https://code.claude.com/docs/en/network-config)：认证、应用内容、Artifacts、Chrome 桥接、MCP 组件等可能涉及 `claudeusercontent.com`、`claudemcpcontent.com` 及其他依赖。仅将客户需要的功能加入候选，不粗放代理整个共享 CDN 或屏蔽遥测来“防封”。源站经自定义网关／云提供商时另核对实际提供商路径。

规则要同时核对：前置／后置／规则集的优先级、域名与进程规则冲突、`MATCH`／`FINAL` 兜底、组内自动选择／负载均衡／故障回退、UDP 不支持时行为。若客户要求固定出口，组内引用自动组、备用 DIRECT 或代理链丢失回退都要说明；用组名相同不能证明出口相同。

## 5. 先写预期，再测各类分流

| 场景 | 需要确认的目标与验证 |
| --- | --- |
| Claude 专用分流 | Claude 已选功能走指定组，其余业务沿用客户既有规则；从实际请求核对命中，不只看文件 |
| 整机统一代理 | 客户明确选择后再设计接管范围及例外；TUN 排除、程序自带解析、UDP、IPv6、VM／WSL 都须标覆盖情况 |
| 国内／海外分流 | 双方按客户约定分别验证；DNS 查询路径与业务连接出站分开，不能凭地区标签判断正确 |
| 应用／进程例外 | 核实实际可执行程序、共享运行时、子进程、目标、协议与地址族；不能把全部 `node`／`python` 进程当成 Claude |
| 链式代理／独立落地 | 核对本机→中转→落地→目标各段，节点解析和链缺失时行为；落地连不上时不偷偷跳过中转 |
| LAN／企业 VPN／远控 | 保留必要本地访问、公司域名与恢复通道；明确例外后不要再宣称全机同出口 |
| 故障时 | 节点坏、GUI 退出、核心停止、隧道消失分开验收；失败是阻断还是直连／其他出口，要有实际观察 |

最终至少验证：核心成功载入、目标规则实际命中、真实客户端正常、必要的国内／LAN／远控业务可用。回滚时核对候选之后是否出现新修改；只有在授权和内容匹配条件满足时恢复原文件／原选择／原开关，恢复后复测。未知保存结果先读回，不盲目重复导入、重启或覆盖。

## AI 专属代理默认策略

自动配置模式按 [Claude / OpenAI 专属规则](ai-dedicated-routing.md) 先生成单节点候选（`ai-route`）与差异，再由客户机 Codex 应用已批准方案。AI 失败不改走 DIRECT，目标 UDP 显式拒绝，其他国内直连／国外代理及原配置保持。`ai-audit` 比较读回后的静态策略；DNS、客户端接管和故障效果另验。
