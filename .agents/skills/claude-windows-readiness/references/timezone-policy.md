# 时区对齐：默认配置项与验证

本包完整配置的默认方案：**自动配置／完整环境搭建默认将系统时区对齐指定稳定出口对应的时区，列入具体方案并执行验证。** 已明确要求保留时区的设备或局部任务继续按用户范围处理；仅检查网络、阅读资料、修改 Skill 不因此修改真实设备。系统语言、输入法、键盘和地区格式保持，浏览器语言按另行目标处理。这是本 Skill 的配置偏好，不是官方“防封”条件。

## 先确定具体目标

- 核对实际执行设备、当前系统时区 ID、自动时区、自动校时和时钟准确性。Mac、Windows、WSL、VM、VPS、手机各自记录，远程显示端的时区不替代远端进程。
- 以本轮选定稳定出口的明确地区和用户目标确定城市／时区。出口 IP 的商业定位可能不准；节点名称、服务器入口地址或 Cloudflare 的 `colo` 接入点不是出口城市的充分证据。只有国家、多个来源冲突或存在多个时区时，补问具体目标，不猜城市。
- 优先使用有夏令时规则的系统时区 ID，不写死 UTC 偏移。Mac 用系统实际列出的标识；Windows 用 `Get-TimeZone -ListAvailable` 的 ID，不直接粘贴 IANA 名称。相同 UTC 偏移不等于相同时区。
- 方案明确写“原时区 → 目标时区／城市、自动时区如何处理、自动校时保留情况、影响和恢复”。目标及范围已获批准就连续执行，不再泛问一次是否要改时区；已有值正确时只核验。

## 执行与读回

1. 保留原时区、自动时区和自动校时原值，以及恢复步骤；优先使用系统支持的设置入口。
2. 按已批准目标调整时区。需要手选时区时只关闭对应的自动时区功能；自动校时是另一件事，能独立保留则继续保留。不能通过改日期或把系统时钟拨快／拨慢来实现时区变化。
3. 若目标平台把自动时间与自动时区合并成一个开关，先说明联动影响并纳入方案；不能声称保留了界面无法独立保留的选项。手机按实际系统版本操作，不套用 Mac／Windows 命令。
4. 重新读取系统时区 ID 和自动选项；检查当前偏移／夏令时规则、日历与定时任务显示。必要时在已允许使用的浏览器档案读取 `Intl.DateTimeFormat().resolvedOptions().timeZone`，与系统结果分别记录；只修改浏览器报告值不算系统时区完成。需要浏览器重启时遵守原网络顺序和手动重启约定。
5. UTC 时钟应仍准确。全 UDP 拒绝可能影响依赖 UDP 的校时路径，需核对实际校时状态；不能把时区正确等同于已经同步，也不为校时擅自放开全部 UDP。有冲突时准备精确校时例外或其他受支持方案，沿用用户选择。
6. 回退恢复本次记录的原时区与自动选项。以后换节点／地区只标记目标漂移并复核，不随每次临时出口自动改变整台设备。

Mac 和 Windows 的具体入口见 [时区与语言模块](locale-and-language.md)。同一出口也不能证明设备位于该地区；时区一致不替代真实网络或账号功能检查。

## 官方依据

- [Apple systemsetup](https://support.apple.com/guide/remote-desktop/about-systemsetup-apd95406b8d/mac)：列出支持的时区后设置，网络时间同步是独立选项。
- [Microsoft Set-TimeZone](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/set-timezone)：ID 与本地化显示名称不同，先用 `Get-TimeZone -ListAvailable` 核对。
