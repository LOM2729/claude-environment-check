# Net.Coffee 教程逐项覆盖表

核对日期：2026-10-21。来源为[域名分流页](https://ip.net.coffee/claude/site.html)及[11项配置页](https://ip.net.coffee/claude/claudecode.html)。本文记录它们与本包的对应关系，供 Codex 在仓库内执行与维护；给客户只输出简短的已完成／未完成清单。

这两页是**社区配置建议**，不是 Anthropic 官方要求。本轮按用户选择把其扩展域名、共享服务、关键词、IP 与分类兜底纳入默认 `domestic-v4` 的补充范围，同时保留原有目录用于旧策略兼容。规则覆盖表示生成器有对应处理，不等于客户机已导入、已生效或账号安全保证。

## 执行和验收入口

按 [五步流程](five-step-setup.md) 执行，先只读采集，再准备具体差异、取得本轮确认、备份导入、读回验收。DNS／代理就绪前不解析或打开 Claude/OpenAI；时区等独立本机项目可并行。需要重启、断开或不确定会否中断控制通道的重载，由客户手动执行，恢复后复查。

Clash/Mihomo 与小火箭均由 Codex 生成、审计相应格式，客户不编辑规则。Windows 原生、WSL、macOS 分别核对实际进程和网络入口；Windows 没有客户实际使用的小火箭客户端时，不把另一台设备的配置生成当作 Windows 运行验收。

Codex 在生成最终候选和读回活动配置后分别运行以下离线检查；参数由 Codex 填写，客户不手动执行。当前随包补充快照展开为148个匹配、444条保护规则，详细结果保存在报告目录。

```text
python <Skill>/scripts/claude_setup.py tutorial-check --config <最终候选或活动配置读回> --node <已指定具体节点> --out <新报告目录>
```

静态检查完成后，实际客户端流量验收仍显示未完成；退出码2表示有待验证项，不是要求绕过检查。报告不执行探测或改变配置。

默认顺序仍为：**AI保护（含本页扩展）→ IPv6拒绝及保留的明确拒绝 → 国内视频直连 → 其余UDP拒绝 → 普通国内域名直连 → 国外统一指定节点**。Claude 专属组与基础组绑定同一具体节点，均不带 DIRECT、备用节点或自动选择。

## IP、ASN、分类及NTP

| 教程项目 | 本包处理 | 不能据此推断 |
| --- | --- | --- |
| `160.79.104.0/21` | 社区选择的IPv4兜底，域名规则后进入同一指定节点，并有失败保护 | 不是全部 Claude/CDN 现用地址的永久清单 |
| `2607:6bc0::/32` | 保留该范围的明确拒绝；系统、核心、DNS IPv6继续关闭 | 本包没有为它启用IPv6代理 |
| `AS399358` | 将核验时公开路由展开为离线CIDR，避免要求客户现场下载ASN数据库 | ASN所有权或路由快照不能证明每个IP只服务Claude；不是实时BGP监控 |
| `geosite:anthropic` | 从固定版本分类数据递归展开后随包分发 | 分类维护者不是Anthropic官方，不保证永不漏项 |
| `geosite:category-ntp` | 离线展开其主机范围；TCP命中同一指定节点，UDP按现有约束拒绝 | 不宣称完成了UDP NTP代理，不把NTP等同系统时区 |
| `geosite:geolocation-!cn` | 不依赖它保护Claude；AI保护始终先匹配 | 通用海外分类自身不保证指定节点或无直连回退 |
| `no-resolve` | 用于已有目标IP的CIDR匹配，避免该规则额外触发正向解析 | 不是逆向DNS保护、DNS泄露开关或未知域名自动发现 |

离线分类基准为 v2fly/domain-list-community 提交 `e8f6d1e5c4a01cda943c0784ffa834340eeab5ae`；ASN快照来自 RIPEstat 的 AS399358 公共路由数据，观测日期 2026-10-20。数据文件内的来源、摘要和实际展开条目才是本次产物依据；维护者更新源站不自动修改客户配置。当前公开IPv4 `/23` 在上述 `/21` 内；IPv6 `/48` 仍被拒绝。生成器不得为“补齐ASN”偷偷联网或开启IPv6。

NTP与本包“除国内视频外拒绝UDP”的既有要求有冲突，因此选择保留拒绝，明确记录**UDP NTP代理未完成：当前策略拒绝UDP校时；下一步为按客户实际校时需求准备独立方案**。不得把阻断NTP当成系统已校时。系统时钟偏差另行读回；如确需UDP校时例外，需说明具体目标与路由范围后处理，不能全局放开UDP。[RFC5905](https://www.rfc-editor.org/rfc/rfc5905.html)说明的是时钟同步；代理NTP不会更改或隐藏操作系统时区。WebRTC/STUN检测也不能验证全部NTP请求。

## 11项配置逐项对应

| 项目 | Codex执行动作 | 完成依据／边界 |
| --- | --- | --- |
| 1. 出口选择 | 记录客户指定节点、适用区域、可观察出口与稳定性；不自行购买或替换订阅 | 不以“住宅”“原生”标签或第三方评分保证免验证、免停用 |
| 2. 出口稳定 | 单节点固定；检查自动测速、回退、负载均衡、订阅更新与GUI当前选择 | 节点名称相同仍须看实际连接链；不承诺供应商对不同目的地使用同一公网IP |
| 3. TCP／UDP | AI目标UDP先拒绝；国内视频直连例外在其余UDP拦截前；核对全局禁UDP位置 | 不将JSON示例的 `network:tcp` 跨格式照搬，不改变节点服务器要求的传输参数 |
| 4. TLS指纹 | 查当前客户端、核心版本、节点协议、已有外层指纹与是否支持Chrome选项；仅准备适用字段的具体差异 | 保持证书校验，不做MITM；支持外层客户端指纹不表示CLI到业务端的内层TLS变成Chrome；不支持时写未完成及下一步 |
| 5. DNS | 分别检查系统、核心、加密解析器、bootstrap、节点解析与浏览器DoH；按既有门槛配置后读回 | DoH URL存在不等于通过代理；TYPE64/65、WebRTC等依当前流程核验，不在准备前访问AI域名 |
| 6. IPv6 | macOS按真实服务、Windows按真实适配器核对禁用，连同核心、DNS和节点外层复查 | WSL/VM单独处理；一个开关不能证明所有旁路均已消除 |
| 7. 专属分流 | 使用Claude专属组并补齐本页目标，绑定与基础组相同具体节点 | 导入后的活动配置、实际分组选择与链路均需读回 |
| 8. 高于通用分流 | 合并后AI保护置顶，检查Global/Direct模式及更高层覆写 | 旧企业拒绝冲突先列出，不能静默删去；规则库初始化完成后再测业务 |
| 9. 连接保活 | 离线准备并审计Mihomo支持版本的TCP保活设置；禁止显式关闭时按批准方案修正 | TCP keepalive、HTTP连接池和代理多路复用是不同功能；不自动开SMUX/MUX；小火箭或未知核心缺正式接口时保留未完成 |
| 10. 并发 | 只读记录同时运行的Claude任务与429等症状；建议新手先减少并行任务、遵守实际账户限额和退避 | “5以内”仅社区起步建议，不是官方固定上限；不自动杀任务、不为分散限速轮换出口 |
| 11. 网络路径 | 网络门槛满足后，在批准范围内比较当前路径的延迟、丢包、失败与重试现象 | 不按洲名或第三方全球Ping替代客户真实路径，不自行切换指定节点 |

## 官方机制与社区经验分别使用

- **官方产品机制**：[Claude Code网络配置](https://code.claude.com/docs/en/network-config)用于核对HTTP/HTTPS代理、环境继承与相应功能主机；文档里的可选遥测不标为每个用户必须开启。
- **核心机制**：[Mihomo规则](https://wiki.metacubex.one/config/rules/)、[全局配置](https://wiki.metacubex.one/config/general/)、[TLS配置](https://wiki.metacubex.one/config/proxies/tls/)用于核对字段与具体语义。核心端口已监听不代表规则库已就绪。
- **社区配置选择**：本文扩展域名、关键词、IP及分类范围按本次要求纳入，预览中列出共享匹配影响。不能写成Anthropic认证的必要条件或防封承诺。
- **本机实测**：只有当前客户设备上的读回、连接链和实际功能结果可以标为本轮已完成；仓库单元测试、合成loopback、小火箭文本审计分别标注，不能相互冒充。

## 给客户只展示简表

详细差异、范围、来源和验证结果保存在本地报告与仓库；客户摘要只列已完成与未完成。示例：

- 已完成：AI固定出口、国内分流与视频例外、DNS和IPv6设置已读回。
- 未完成：代理需重启——请手动重启后告诉我，继续验收。
- 未完成：UDP NTP代理——当前策略拒绝该流量；如需要系统校时，下一步检查实际时钟与可用校时方式。

不要把计划修改、已生成候选、已测试仓库代码写成客户机已配置；无需客户手工编辑数据文件。任何未完成项都保留准确原因与可执行下一步。
