# 按来源方法优化后的实际工作流程

这是五步流程的任务分支与检查卡。**操作顺序只由 [五步流程](five-step-setup.md)维护**：准备 → 具体方案确认 → 执行选定分支 → 核验需要的功能 → 交付。普通配置保留快速路径；资料整理停留在文档层。此页不添加执行器，不把参考工具的按钮说成本包已有功能。

## 先确定本轮结果

开场从已有信息确定任务、执行位置和当前事故；只补会改变结果的缺口。同一电脑的浏览器、Desktop、CLI、后台、WSL/VM/远端分别绑定，不用本机结果替远端。

| 本轮任务 | 最小交付 | 不自动展开的项目 |
| --- | --- | --- |
| 资料整理/Skill优化 | 来源、方法、条件、证据与文档差异 | 设备采集、探针、安装、清理、登录 |
| 已有环境诊断 | 明确故障入口、实际认证/路径、下一项最小检查 | 改语言、全盘清理、重装或新购资源 |
| 首次/完整配置 | 具体候选、原值/恢复、网络与所用客户端正常功能 | 账号采购、身份轮换、故障注入、常驻防护 |
| 浏览器/客户端清理 | 指定Profile/配置根、类别、备份/隔离和保留项核对 | 其他Profile、历史/凭据/云端删除、全资料reset |
| 身份迁移/程序维护 | 正确对象、检查点、实际提交/重开状态与恢复 | 改出口、删除其他身份、把导入当有效登录 |
| 持续防护/VM/VPS | 选定路线、独立救援、正常/故障/恢复证据 | 叠加互斥策略或把一次检测说成持续保护 |
| 当前账号限制/凭据事故 | 保留证据、定位来源、本人官方处置/导出 | 由错误码自动推导清缓存、换号或换IP |

## 五步的共同检查卡

| 阶段 | 必须准备或取得的结果 | 失败时下一步 |
| --- | --- | --- |
| 1 准备 | 目标/范围、活动配置与版本、必要依赖、影响、原值、备份与独立恢复；网络任务另核隐含请求与业务例外 | 缺能力只准备候选；归属未知先只读；无救援不做会失联的修改 |
| 2 具体方案 | 精确对象、变更/保留项、数据损失、外部目标、重启影响、恢复和验证；复用已有有效批准 | 先备齐可审阅内容；新增范围另说明；不逐开关重复问 |
| 3 执行分支 | 紧邻动作复核同一对象；逐阶段记录实际变化，部分失败保留当前位置和检查点 | 先对账，保护后续编辑；不把超时/非零退出推导成没有写入，不盲重试 |
| 4 核验 | 文件读回、应用载入、实际进程采用、所需功能分别给证据；需要联网/启动AI时先满足本轮网络前置条件 | 未知保持未完成；只补受影响的检查，不恢复旧绿灯 |
| 5 交付 | 简短已完成/未完成、原因和下一步、恢复材料；持续防护另附事件范围 | 实际中断才保存续接点；恢复先查变化，不能从头重装 |

## 默认配置与可选路线

默认继续使用 `domestic-v4`、指定稳定节点、既有国内/视频例外、精确接口及代理层IPv4-only、系统语言保留和已确认的出口时区目标。它与Guardian整机统一转发UDP、cc-hahaeasy自动择优是不同政策，准备时选一条完整目标，不拼接相反规则。

严格IPv4-only分别核系统接口、核心、DNS、规则/防火墙、节点外层和远端出口；AAAA空、超时、偏好IPv4都不能代替阻断。统一双栈保留为可选来源方案，但当前生成器/`dns-ready`不提供双栈通过模式，须另设相应配置与验收，不能为过门槛擅自关IPv6或伪造记录。

## 阶段3：按任务采用具体方法

### 网络与持续防护

网络路线先准备/应用并读回持久化来源和实际运行配置，核验非AI DNS/路径后，才启动/登录/更新或发出实际AI请求。浏览器DoH、WebRTC、Desktop UDP与CLI/远端分别核对；工具报错和无候选不能填通过。

持续防护仅在明确需要时加入：正常TUN/出口先通 → 记录有效规则及管理/LAN/DNS例外 → 准备独立本机救援与原值恢复 → 建立限时恢复保护 → 应用系统层策略 → 窗口内验证 → 再持久化。节点/网卡/换网变化重新确认覆盖；主动暂停/彻底退出与崩溃/断线的预期行为分别写清。具体源方法在 [Guardian网络/PF/Switch](source-methods-guardian-network.md)。本包没有实现该常驻引擎。

### 清理与卸载

准确Profile/origin/存储类别或有效CONFIG_DIR → 识别共享凭据/历史/集成 → 保存任务并停止目标写入者 → 完成一致私有备份 → 精确清单/隔离 → 对账原位、隔离和保护项 → 按需恢复。缓存、登录、历史、配置、全Profile、程序卸载、服务端撤销/云端删除分别选择；默认仅选已确认可再生缓存。

Guardian C5上限为16根/4096项/64MiB/深度32，源实现仅POSIX；不能套作任意容量Windows全清。CCBaga部分直接删除不先备份，局部缓存与全Profile reset保护强度不同，需要恢复保证时另准备备份。Keychain整项删除与字段级OAuth清理不同。见 [浏览器](browser-cleanup.md)、[客户端](client-cleanup.md)、[事务与独立恢复](source-methods-guardian-runtime-recovery.md)。

### 身份、迁移与程序更新

明确选保存/更新备份、切换/空身份、删除当前身份、删保存卡或跨机迁移；分别列保留类别与副作用。执行前检查未完成恢复日志、必要进程和归档，保留检查点；动作提交成功但B重开失败时只重开B，不再切换或导入。

CCBaga迁移仅同OS，导入新增已保存身份、不自动切换；可选浏览器部分只带指纹配置，认证材料仍可能敏感。包恢复不保证DPAPI/Keychain和远端令牌有效。程序维护按实际安装来源，先取得可信安装器/恢复材料，再移旧程序；捕获到的失败回滚不保证断电/强杀恢复。A单独更新和A+B整包更新分别验收。见 [原生身份与资料保护](source-methods-ccbaga-native.md)、[界面/CLI/更新维护](source-methods-ccbaga-ui-maintenance.md)。这些是可选第三方方法，不是本包新增的执行接口。

### VM/VPS与账号

先分清程序执行机、代理中转和公网出口；按架构、内存/OOM、磁盘/流量、管理救援与实际协议选路线。SSH身份核对/第二会话/带外救援先于防火墙；临时noVNC仅回环并经SSH转发，OAuth后关闭专属实例。共享静态NAT、独享公网和原生/住宅标签分别核；17份历史报告见 [样本方法](source-methods-vps-reports.md)。

注册/订阅仅在有明确目标时接入第4阶段，网络就绪后由本人处理登录、支付和身份核验；已有账号不重注册。等待天数、并发/触顶次数与存活率保留在 [完整分类](complete-environment-method.md)及来源方法中，标经验未证，不设为必过门槛。

## 阶段4：恢复与验收必须能回答什么

- 正常使用验证本轮真实入口；系统策略、文件、UI和进程互不代证。清理可离线核原位/隔离/保护项；需要重登、重开或外部请求时再走网络前置条件，不为了验收主动暴露秘密。
- 有新数据或后改时保留双方，先reconcile/检查点再精确恢复；多个文件/数据库/系统状态不是同一原子事务。服务端删除和会话撤销不能承诺由本地备份撤销。
- 只有选定持续防护时才按需覆盖停核心/节点失联、重启、睡眠、换网、新网卡、地址更新、订阅/客户端更新及控制通道中断。不能用单次请求失败证明全机无直连，未发生事件保留未完成；不为清单完整故意拔电或断开远控。
- 以后复查从配置/入口/网络/版本变化开始，复用仍有效证据。新网卡、出口漂移、反复故障才扩查受影响项，不日常全量重配。

## 来源如何改变了流程

| 来源做法 | 我方吸收 | 保留的差异/纠正 |
| --- | --- | --- |
| Guardian入口访谈→路线→能力→检查/修复→验收/恢复 | 先分任务/目标/能力，形成可恢复的闭环 | 不导入每阶段重复审批；pass/established、24小时标签和文案测试不自动通过 |
| CCBaga扫描/保留策略→stop→动作→刷新/恢复 | 清楚展示对象、进程中断、部分完成、重开与迁移的真实结果 | 不把所有动作称为可恢复；组合语言修改不成为默认 |
| cc-hahaeasy启用→保护→巡检/自愈→暂停/恢复 | 区分正常/故障阻断/暂停/退出/到期，给出恢复入口 | 官网动画是演示；服务状态非本机检测；桌面/后端源码未取得，效果仍未验证 |

## 选用方式与验证状态

默认按既有用户目标执行，可选方法只有选中后才进入方案；未经验证的机制/目标结果与账号因果分别标注；已经纠正的解释不再作为“也许有效”的方案。完整依据与实际阅读范围见 [来源覆盖](source-coverage.md)。本轮仅优化文档，没有实施清理、系统网络修改或故障试验。
