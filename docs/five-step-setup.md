# 五步自动配置：客户只做选择，Codex 负责执行

**当前教程扩展：** 默认按 [教程覆盖表](tutorial-coverage.md) 逐项处理全部列出的目标、分类与 11 项建议；新增共享范围进入具体方案。先按 [连接保活](connection-reuse.md) 准备适配候选，再生成统一分流；最终全量差异和规则审计分别绑定正确输入。运行 `tutorial-check` 检查静态逐项覆盖，运行态仍需目标机验收。客户只看简短结果。

**v0.10 专属组验收：** 默认 domestic-v4 为 Claude 第一方域名增加 <基础组名>-Claude（默认 AI-ONLY-Claude），与基础组绑定同一具体节点，AI保护块仍优先。生成后检查最终合并和运行连接链，按 [分组与服务路径检查](service-routing-checks.md) 验收；旧候选迁移需先审阅差异。

**v0.8 顺序补充优先适用：** 自动模式采用 [国内视频 UDP 与国内域名](domestic-video-udp.md) 的 domestic-v4。先检查全局 UDP 限制层级；AI 保护优先，视频直连在其余 UDP 拒绝前，普通国内域名在拒绝后。旧 unified-v4 示例仅兼容旧策略；本轮 ai-route / ai-audit / baseline 明确使用 --policy domestic-v4。小火箭由同一策略生成原生 .conf，按 [小火箭适配](shadowrocket-domestic.md) 导入与读回，不套用 Mihomo 文件格式。

本文件是自动配置的顺序入口，优先于旧参考中的章节排列。默认目标：**国内及已确认的本地例外直连；普通国外与 Claude/OpenAI 共用一个指定节点；关闭选定联网接口及代理层的 IPv6；系统显示语言不改。** 具体策略见 [统一出口与 IPv4](unified-ipv4.md)。报告只用已完成/未完成。

客户只需提供已有配置/订阅、在必要时选择一个已有节点、确认一次具体方案，以及处理本机认证/登录。路径、端口、参数、JSON 与工具输出由 Codex 识别和填写；无法确定时只问当前关键缺口，不让客户照抄命令。

## 1. 准备：先了解本机，不打开 AI

- 识别 Mac/Windows 原生执行端、代理客户端/内核、实际 profile、现有文件和 Python；用文件元数据、PATH 和系统安装清单识别 AI 客户端，先不运行 Claude/Codex CLI、doctor、auth、更新或安装命令。
- 先盘点已有 AI 进程、浏览器标签/恢复会话、自启与安装器完成后启动选项。当前已运行的 Codex/远控属于控制通道，不能自动杀掉或断开；其他会话需要保存和退出时写入方案并取得已有或本次明确批准。
- 没有基础网络、在线 Codex 尚不能使用的电脑，先由操作者使用本机离线说明、已有可信代理安装包和订阅完成基础准备，再让 Codex 接手。不能宣称在线 Codex 能保证自身第一次联网之前零 AI 请求。代理软件下载也可能联网，来源及范围先说明。
- 本地读取、备份、时钟准确性、时区方案可以独立准备；完整配置默认对齐指定稳定出口，具体目标不清先补问，批准后执行并读回。语言设置只处理明确目标，系统语言保留；**浏览器重启/恢复标签页不是纯本地动作，必须后置。** 初期用聊天/文本展示报告，不为展示离线 HTML 而提前启动浏览器。

## 2. 确认方案：一次确认，先备份好

展示五行即可：保留什么、改什么、为什么、影响与恢复、如何验证。把所选节点、DIRECT 例外、IPv6 的精确接口范围、DNS 引导路径、必要安装/重载、非 AI 检测站点及后续 AI 验证列清；客户确认后连续执行，不为同一具体批准反复询问。

备份当前配置、关联扩展、选择状态和必要应用设置，并把恢复说明放在本机。IPv6 原模式/绑定及稳定接口身份需要单独记录；manual 模式还需原地址/前缀/路由。备份不齐或唯一控制通道可能断开时，不执行该网络变更，继续独立项。

## 3. 配置并核验网络：先排除隐含请求

1. 静态检查节点地址、IPv4 可用性、节点域名引导解析与 DNS 上游依赖，避免解析节点又依赖尚未建立的代理。只节点订阅不等于完整分流/DNS配置，由 Codex 从当前客户端核对/导出完整配置。
2. **核心校验、导入、启动、重载、订阅刷新之前**，对当前/候选配置运行 `contact-scan`，核对 url-test/fallback、provider health-check、资源下载、脚本和节点/DNS上游。还要看软件界面的额外测速、AI 解锁检测、自启和自动订阅刷新。
3. 检出 AI 或无法确认的行为时暂停启用。Codex 在方案中明确提出关闭该自动测试、换成已批准非 AI 诊断地址，或先物化并审阅外部内容；批准后才修改，再扫描。扫描不会替客户改 URL。不能因为“只是配置校验”就直接运行会联网的核心命令。
4. 用 `direct-review` 盘点非显然的 DIRECT 规则，按本轮目标保留国内/必要本地例外、把确认的国外直连改为代理。再以 `ai-route --policy domestic-v4` 准备候选，核对差异；不静默丢弃企业/LAN/远控例外。 隐含请求调整在最终候选生成前完成。若之后又改 URL/DNS 等字段，重新生成对应直连审阅、候选、plan 并重扫描；不要改旧快照或忽略审计不匹配。最终导入的完整差异以原活动配置到最终候选为准，统一规则审计保留生成器实际输入。
5. 用当前版本支持的持久化入口保存；只有已确认不会中断控制通道的热重载才由 Codex 执行。需要重启代理客户端/核心/服务，或重载的断线影响不明时，按下方“客户手动重启与恢复”交接，不自行退出或重启 Clash。重新读取最终运行配置；不能只检查桌面原文件、订阅源或扩展。未知软件字段不能猜着改。
6. 按精确接口方案关闭 IPv6、读回；`ipv6-check` 必须取得关闭状态。代理内核/DNS/节点外层与操作系统分开验证。依赖 IPv6 的节点、DNS、企业网或远控先解决兼容，不冒充完成。
7. 用 bootstrap 非 AI 计划验证 DNS、代理路径和国内/国外分流。不能用一次解析到 Fake-IP 或同一 HTTP 端口当作同节点证明；核对运行中规则与连接链。
8. 记录真实 DNS/代理证据与 IPv6 关闭范围，生成本轮 `dns-ready`。v2 记录绑定精确接口与代理入口，旧记录需重新核验。记录不是额外授权或自动路径证明。

工具命令由 Codex 填写：

```text
python <Skill>/scripts/claude_setup.py contact-scan --config <候选或实际配置> --out <新报告目录>
python <Skill>/scripts/claude_setup.py action-check --action proxy-load --config <候选配置> --out <新报告目录>
python <Skill>/scripts/claude_setup.py ipv6-check --interface <实际服务或适配器名> --out <新报告目录>
python <Skill>/scripts/claude_setup.py dns-ready --config <实际配置读回> --proxy <已核验HTTP入口> --ipv6-interface <同一接口名> --readback-verified --dns-path-verified --proxy-path-verified --evidence <真实脱敏证据> --output <新记录.json>
```

多个接口重复 --interface / --ipv6-interface。contact-scan/action-check 只检查，不执行动作。静态结果不保证软件运行时不存在其他行为，外部内容和 GUI 设置要另核对。

### 客户手动重启与恢复

Mac 与 Windows 均适用；并非每次重载都需要重启。按当前客户端的实际提示决定，不能为了让配置生效反复重启。

1. **先保存进度。** 在客户本机私有目录保存已完成/未完成清单、原配置备份、候选文件位置和哈希、当前步骤、待执行动作、后续读回项目与离线恢复方法。恢复说明须能在断网时打开，不能只给在线链接；不将订阅凭据写入聊天。
2. **交给客户操作。** 仍能联络时说明具体软件、需要点击的动作、可能暂时断线及恢复步骤。代理应用/核心/服务或整机需要重启时，始终由客户手动执行。TUN、系统代理、网卡绑定（包括 Windows 关闭 IPv6）等动作若可能影响当前 Codex/远控通道，也交给客户。不得使用定时任务、后台脚本、杀进程或服务命令代替客户重启；影响不明同样交接。集中批准方案不覆盖这一人工交接要求。
3. **等待恢复。** 相关项显示“未完成：等待客户手动操作并恢复连接；下一步：完成上述操作后回复已恢复”。客户准备好再操作；不在等待期间执行依赖该网络状态的动作。客户未回复、时间经过、进程出现或点击完成均不能视为恢复成功。可继续不影响连接的独立本地工作。
4. **重新核验再继续。** 客户回复已恢复后，从保存的步骤继续，重新读回活动 profile/核心、指定节点、DNS、精确接口 IPv6 状态，并做已批准的非 AI 路径验证；生成新的 dns-ready，旧核验记录不可复用。通过后才允许 AI 验证与客户端启动。不仅凭客户确认就标已完成，也不重复询问同一批准范围。
5. **恢复失败。** 保持未完成，按预先保存的离线说明让客户恢复原配置/选择状态和相关设置；不要盲目重导入或连续重启。恢复后同样重新核验。

## 4. 打开服务：每个入口都要过当前核验

允许 AI 服务探测后，才按所需范围执行安装/更新、打开网页、启动/激活应用、重启浏览器、恢复会话和登录。安装器下载本身也可能请求 AI 域名；不能提前做。登录、验证码由客户本人处理。

```text
python <Skill>/scripts/claude_setup.py action-check --action <动作类型> --config <实际配置> --proxy <同一入口> --dns-ready <本轮记录> --out <新报告目录>
```

动作类型：`browser-start`、`browser-restart`、`client-install`、`client-update`、`client-start`、`client-login`、`cli-diagnostic`、`service-page`。若记录包含浏览器偏好，另传相同 --browser-preferences。动作检查不会替客户点击或安装，仅给执行依据；Codex 必须紧邻实际动作使用新结果。

原生启动可用 `preflight --launch`，它在最终启动前再次核验记录、当前状态和代理入口；过期/变化则不启动。首次使用先在网络配置读回后保存配置基线，基线不表示客户端已验收；实际业务验证后再完成交付记录。不要形成“必须先启动验收才能创建启动所需基线”的循环。

安装/更新/切网等动作改变了配置或有效状态后，旧记录失效，先复查；不复用旧通过结果。已运行会话可能不读取后来修改的代理变量，需在批准范围内重建并验证。实际客户端登录、模型请求、上传等与探针结果分别记录。

## 5. 交付：只说结果和下一步

报告显示已完成/未完成、未完成原因和一个可执行的下一步。Codex 保存本机私有基线、差异、恢复方法与证据；客户不编辑 JSON。中断后从未完成步骤继续，重测变化影响的依赖，不从头重装或刷新旧证据时间。

默认仅请求一次启动，不安装常驻守护或系统防火墙，不宣称持续 Kill Switch。旧进程与已发出的流量不能追溯阻断。小火箭没有真机导入/运行证据时，对应项继续未完成。
